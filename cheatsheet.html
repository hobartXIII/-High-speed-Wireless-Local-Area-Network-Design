④ 答題骨架

  • 比較／差異：一句定位 → 逐面向對照（運作方式、誰控制、碰撞、確認、效率、延遲／QoS、公平、省電、安全、適用組態）→ 各適合什麼。畫表
  • 優缺點：優（效率、延遲、公平、簡單、相容）／缺（負擔、延遲、複雜、需協調者、隱藏節點、組態限制、無保證）→ 誰改進它（後繼機制）
  • 為什麼這樣設計：③ 找特性 → 沒有它會怎樣 → 它怎麼解 → 代價
  • 反事實（X 改用 Y）：Y 的前提在 X 的環境成立嗎 → 失去什麼 → 結果（正確性、效率）。例：無線用 CD＝做不到；有線用 CA＝能用但多等待、多 ACK
  • 「不用某機制」：從四類工具找替代：架構（AP、輪詢）、時間（IFS、EIFS、NAV、退避）、訊框（分段、短訊框、Duration）、PHY（功率、門檻、速率）
  • 解釋題：目的（解決什麼）→ 運作（誰送、何時、什麼欄位）→ 例子或相關機制
  • 定義題：一句定義 → 發生條件或圖 → 後果 → 對策
  • 計算題：畫時間軸 → 列每段時間 → 加總 → 一句解釋數字代表什麼

機制卡（續背面）

K1CSMA/CD＋BEB（802.3）

目共用一條線時決定誰送

運聽 → 邊送邊聽 → 撞：jam 32 bits → 第 n 次碰撞等 r∈[0, 2k−1] slot，k＝min(n,10)，slot 51.2 µs（來回傳播＋偵測）；n＞16 放棄

＋撞了立刻停、浪費小；送完沒撞≈成功 → 不需 ACK

－先進後出不公平；負載高延遲大；需最小訊框 64 B、距離受限；只能有線

比K2：CD 撞後才退避、不凍結；CA 忙過就退避、凍結

K2DCF（CSMA/CA）

目沒有中央控制下公平共享

運CCA＋NAV 閒 → DIFS → 退避 → 送 → SIFS 後 ACK；失敗 CW 加倍。必備；ad hoc、infra 都用；PCF／HCF 建在其上

＋分散、穩健、高負載穩定、近似 FCFS

－沒有 QoS；負擔大（前導、IFS、退避、ACK）；隱藏節點；頻寬公平不保證（每站用到的頻寬可能不同 → 講義問：要不要負載分擔）

比K1、K9、K21

K3IFS 訊框間隔（含 EIFS、AIFS）

目用「等多久」給優先權，不用額外訊框

運SIFS（ACK、CTS、回應 Poll、分段間）＜ PIFS（PC）＜ DIFS（DCF 資料）＜ EIFS（收錯後）。EIFS 不看 NAV（讀不到 Duration），留時間讓別人以 1 Mbps 送完 ACK。11e：AIFS[AC]＝AIFSN×slot＋SIFS，＞ SIFS 以保護 ACK；11n RIFS

＋SIFS 讓一次交換不被插入；PIFS 讓 PCF 搶在 DCF 前

－DCF 只分訊框種類，所有站的資料都是 DIFS → 不分流量

K4退避與 CW

運Random[0, CW]×slot；忙時凍結、閒 DIFS 後續數；失敗 CW 加倍（DSSS 31→1023；OFDM 15 起）；傳完還有下一筆也要退避；空閒 ≥ DIFS 可直接送

＋等越久剩越少 → 近似 FCFS；不讓贏家霸佔

－閒置也在等；失敗者 CW 大，仍吃虧

比BEB：撞後才退避、單純等待；初始範圍小（碰撞便宜）vs CA 大（碰撞貴）

K5正向 ACK

目偵測不到碰撞與錯誤 → 靠回覆確認

運收對（CRC 正確）→ SIFS 回 ACK；沒 ACK＝失敗 → 退避重傳至上限（短／長重試計數）；Data、Poll、Request、Response 要 ACK；廣播不 ACK。ACK 遺失 → 重複 → Retry 位元＋序號刪除

＋MAC 層快速復原，不必等上層

－每訊框多 SIFS＋ACK（含 PLCP）

比Ethernet 不用：能 CD、可靠、上層 LLC／TCP 處理；11e 改 No Ack、Block Ack

K6RTS/CTS＋NAV；隱藏／暴露節點

目讓聽不到傳送端的站也知道媒介被佔用

運RTS（Duration）→ CTS（Duration）散布到傳送端與接收端兩邊 → 存入 NAV；NAV 或 CCA 任一忙就延後；只用於 unicast，超過 RTS_Threshold 才用（選用但必須實作）

＋碰撞只損失短 RTS；NAV 在多速率下仍有效

NAV 的來源：RTS/CTS、分段與 ACK 的 Duration、CFP 開始設 CFPMaxDuration（CF-End 重設）、11g 保護用的 CTS、QoS CF-Poll（polled TXOP）；PLCP 的 LENGTH 也讓低速站知道要忙多久；收錯訊框讀不到 Duration → 改用 EIFS

－多兩訊框＋2 SIFS，短訊框不划算；不解暴露節點

隱藏：A、C 彼此聽不到，同時送給 B，在接收端撞。暴露：C 聽到 B 而延後，其實傳給 D 不干擾 A；但 C 也收不到 D 的 ACK

不用 RTS/CTS：infra 模式（都聽得到 AP）、PCF／HCCA 輪詢、分段（Duration 當虛擬 RTS/CTS）、EIFS、調功率或偵測門檻 補充

K7分段與重組

目錯誤率高 → 短訊框；錯了只重送一段 補充

運≤ Fragmentation_Threshold、等長（最後一段可短）、同序號、分段號遞增、More Frag；SIFS 連送（burst）各自 ACK；每段 Duration 涵蓋下一段＋ACK＝虛擬 RTS/CTS，最後一段＝0；接收計時器逾時就丟

＋錯誤時重傳量小

－多標頭、PLCP、ACK

比802.3 有最小訊框、不分段（可靠）；ACK 遺失時，只聽得到目的端的站可自由存取

高速無線區域網路設計 期中小抄 ②：機制卡、公式目目的 運運作 ＋優點 －缺點 比比較

K8廣播／群播

不用 RTS/CTS、不 ACK、沒有 MAC 復原（ToDS＝1 送給 AP 的例外）；自己也會收到，要過濾自己的 SA；有人省電時等 DTIM 後送；傳遍整個 ESS

K9PCF

目時間受限服務、無競爭

運PC 在 AP；PIFS 後送 Beacon → 全體 NAV＝CFPMaxDuration → CF-Poll（可合併 Data＋CF-Ack）↔ 被點者 SIFS 回應（沒資料回 Null）→ CF-End 重設 NAV → CP 用 DCF。CFP 每若干 DTIM；Beacon 延後 → CFP 縮短，最晚 TBTT＋CFPMaxDuration 結束

＋無碰撞、延遲變化小；與 DCF 共存在同一超級訊框；捎帶確認；都聽得到 AP

－一次 Poll 一個訊框；PC 不知 QoS 需求 → 不保證頻寬、延遲、抖動；CFP 會縮短；輪到沒資料的站浪費；只有 infra；對 PC 隱藏的站不設 NAV 會干擾；商用幾乎沒做

比K22 HCCA 逐點改進

K10TSF 同步、Beacon、TBTT

目全 BSS 對時：省電、PCF 時序、FH 跳頻、S-APSD 都靠它

運infra：AP 在 TBTT 送 Beacon（timestamp）；依排程，不是相對上一個；不必每個都聽到。IBSS：每個 TBTT 隨機 [0, 2·CWmin·slot]，先聽到別人的就不送

Beacon 內含 timestamp、間隔、能力、SSID、速率、參數組（CF）、TIM；Probe Resp＝Beacon 但沒有 TIM

K11省電（infrastructure）

運Pwr Mgt＝1 告知 AP → AP 緩衝 → 站台在 Beacon 前醒看 TIM（依 AID）→ 有就送 PS-Poll（AID）、保持清醒（More Data＝1 表示還有）→ 沒有就再睡；廣播／群播等 DTIM（TIM 間隔的倍數）

＋對上層透明；可在吞吐量／延遲與電池之間取捨

－要等 Beacon：100 ms 間隔 → 延遲 100–300 ms；每筆一個 PS-Poll

比K26 APSD

K12IBSS（ad hoc）與 ATIM

沒有 DS → 只有 SS、只有 Class 1、BSSID 用亂數、Beacon 分散產生

省電：TBTT 前醒 → ATIM 視窗內送 ATIM → 對方 ACK、醒到下一個視窗結束；視窗內只能送 RTS、CTS、ACK、Beacon、ATIM；視窗後用 DCF 傳資料

K13掃描

Passive：每頻道聽 Beacon ≤ ChannelTime；不發射、省電 補充，但慢。Active：送 Probe Request（SSID 或廣播）→ MinProbeResponseTime 內沒回就換頻道，有回就等到 Max；快，但耗電、佔頻道 補充

用途：加入網路、漫遊找新 AP、建 IBSS；找不到可自建 IBSS

K14認證、關聯、漫遊、狀態

目認證取代「接上線」；關聯讓 DS 知道 STA 在哪個 AP

運State 1 →（認證）→ 2 →（關聯）→ 3。Class 1：RTS、CTS、ACK、Beacon、Probe、Auth、Deauth、ATIM；Class 2：(Re)Assoc、Disassoc；Class 3：經 DS 的資料、PS-Poll。收到未認證者訊框 → 回 Deauth。Class 1 為何不用認證：找網路（Beacon、Probe）和共用媒介（RTS、CTS、ACK）是加入前就必須做的 補充

認證在鏈路層，非端對端；Open System／Shared Key（挑戰／回應）。一個 STA 同時只關聯一個 AP；可對多個 AP 先認證（預先認證 → 漫遊更快）

漫遊：品質差 → 掃描（或用先前結果）→ Reassociation Req → 新 AP 通知 DS，舊 AP 經 DS 得知；L2 IAPP（11f）、L3 Mobile IP

K15DS、Distribution、Integration、Portal

目位址≠位置時，仍讓上層看到一個 802 LAN

運DS 把 BSS 串成 ESS（對 LLC 像一個 BSS）；Distribution 依關聯資訊找輸出 AP；目的地在有線 LAN → 輸出點是 Portal，Integration 做媒介與位址轉換。802.11 只定義服務，不定義 DS 怎麼做。橋接器 vs Portal：橋接器原本延伸同類 MAC 的範圍，802.11 的涵蓋改由 ESS 提供；接到異質 LAN 時要接 DSM 還是 WM？→ 用 Portal，它還要處理 BSS 成員動態變化與位址／位置對應

SS（每台都有）：認證、解除認證、隱私、MSDU 傳遞；DSS：關聯、重新關聯、解除關聯、分配、整合；＋QoS

K16四個位址

To/From：00 DA、SA、BSSID（IBSS）｜01 DA、BSSID、SA（AP→STA）｜10 BSSID、SA、DA（STA→AP）｜11 RA、TA、DA、SA（WDS）

為何無線這一跳的收／送端 ≠ 原始來源／最終目的；AP↔AP 時四個都不同。A1＝接收端（大家用它過濾），A2＝傳送端（ACK 回給它）。控制 1–2 個、管理 3 個、資料最多 4 個

K17標頭欄位

Duration/ID：µs → 別人設 NAV；CFP 中 32768；PS-Poll 放 AID。More Data：AP 還有緩衝（或 STA 還有資料回 CF-Poll）。Retry：重傳，用來去重複。Pwr Mgt：1＝要睡（AP 送的恆為 0）。More Frag：後面還有分段。Seq：12-bit 序號＋4-bit 分段號

K18WEP／隱私

目補回有線「封閉媒介」的機密性

運RC4：40-bit 金鑰＋24-bit IV；ICV 檢完整性；只加密資料的 payload、每個 MPDU；ICV 錯照樣 ACK 但丟掉；關聯前要議定隱私演算法

－只保護無線一段（非端對端）；金鑰分配沒標準化；已被破解 → 11i 補充

K19PLCP 與多速率

Long PLCP：前導 144＋標頭 48 bits，都用 1 Mbps → 192 µs；Short：96 µs。為何用最低速：大家都看得懂；LENGTH＝要傳幾 µs → 聽不懂資料的站也能虛擬載波偵測。速率選擇不在標準內（做法如依 ACK 成敗或訊號品質升降速率 補充）。一個 BSS 用一個頻道（FHSS 是一起跳頻）；要多頻道就是多個 BSS 共址 補充。11g：有 11b 站時先送 CTS 設 NAV 再用 OFDM。減少 PHY 負擔：short preamble 96 µs（11b）、short slot 9 µs（11g，BSS 內有舊站就不能用）

K20調變與展頻

DSSS：每位元 11-chip Barker，編碼增益 10.4 dB → 抗干擾、抗延遲擴散、分辨回波；代價：頻寬變寬（每個訊號約 22 MHz 補充）。2.4 GHz 頻道間隔 5 MHz，不重疊 1、6、11 → 重疊 BSS 最多 3 個

鍵控：PSK 相位、FSK 頻率、ASK 振幅。QAM：I（cos）、Q（sin）各做 ASK 再相加＝PSK＋ASK；16-QAM 24、36 Mbps，64-QAM 48、54 Mbps；每符元位元越多、越需好的 SNR 補充。DBPSK 1 bit、DQPSK 2 bits／符元

K21EDCA

目優先式 QoS（相對高低）

運UP（8 個，同 802.1D → 有線的優先權標記可直接帶進來）→AC：1、2 BK｜0、3 BE｜4、5 VI｜6、7 VO；競爭在 AC 之間，每個 AC 有自己的 AIFS、CW、TXOP limit；參數由 AP 在 Beacon 的 EDCA Parameter Set 宣告（ACM＝強制允入）。預設：VO 2＋0–3、VI 2＋0–7、BE 3＋0–15、BK 7＋0–15 slot

＋分散、相容 DCF、可動態調參數

－統計式，不保證；低優先可能餓死；同台 AC 內部碰撞 補充

K22HCCA、TSPEC、允入控制

目參數化 QoS（如 10 Mbps、10 ms）

運ADDTS Req（TSPEC）→ HC 判斷允入 → ADDTS Resp → 依 TSPEC 排程 → QoS CF-Poll → Polled TXOP；CFP 與 CP 都能輪詢；TID 8–15；DELTS 刪除

＋可保證頻寬與延遲。vs PCF：一訊框 → 一段 TXOP；不知需求 → TSPEC；無保證 → 排程＋允入

－需 HC、複雜、只有 infra、隱藏站。允入控制：不超賣才能守住已允諾的保證

K23TXOP

開始時間＋最大長度；EDCA TXOP（贏得競爭，上限在 Beacon）／Polled TXOP（收到 QoS CF-Poll，上限在 QoS Control）；內部以 SIFS 連送；單位 32 µs，32–8160 µs

＋一次競爭送多筆、分攤負擔；以時間限制佔用。－長了別人等得久（VO 短、VI 長）

K24ACK 政策與 Block Ack

Normal（SIFS 後 ACK）／No Ack／No explicit／Block Ack。BA：ADDBA（TID、政策、緩衝、逾時）→ QoS Data 連發 → BAR → BA（點陣圖最多 64 MSDU）→ DELBA

Immediate：高頻寬低延遲。Delayed：先回 ACK，之後再送 BA，可容忍中等延遲。＋省每筆 SIFS＋ACK。－要建立、要緩衝重排。No Ack 適合語音 補充

K25DLS

經 QAP 交換 DLS Req／Resp（可叫醒省電的接收端、交換能力）→ QSTA 直接互傳 → DLPTimeout 沒流量就失效、回到經 AP；期間接收端不能省電。解決 AP 頻寬用兩倍的缺點

K26APSD

U-APSD（WMM PS，以 EDCA 為基礎）：醒來送 trigger（上行資料）→ 服務期間 SP → QAP 送可遞送 AC 的訊框（≤ Max SP Length：全部／2／4／6）→ EOSP 結束。S-APSD（以 HCCA 為基礎）：ADDTS 協商排程，定時醒來

VoIP：每 20 ms 一包、要 ＜20 ms；上行語音順便當 trigger → 不必等 Beacon、省 PS-Poll；其他 AC 仍走 PS-Poll

K27架構與 AP

IBSS（ad hoc）／Infrastructure（AP＋DS）／Mesh；BSS＝單一協調功能控制的一群 STA；AP＝STA＋DS 存取；802.11 只標準化空中介面（PHY＋MAC）

全部經 AP：－頻寬兩倍、競爭與碰撞多；＋解隱藏終端、省電緩衝、AAA、每流 QoS
