1. 標準依據

  • IEEE 802.3：Carrier Sense Multiple Access with Collision Detection（CSMA/CD），即 Ethernet 的 MAC 與 PHY 標準。
  • 上層依據：IEEE 802.2 LLC；再往上是 IP、TCP、HTTP、FTP、SMTP 等高層協定。
  • 補充802.3 源自 DEC、Intel、Xerox 制定的 DIX Ethernet（Ethernet II）。差別在訊框第 13–14 byte：802.3 當作 Length，Ethernet II 當作 Type；數值 ≤ 1500 視為長度，≥ 1536（0x0600）視為 EtherType，所以兩種格式能共存。
  • 補充後續修訂：802.3u Fast Ethernet 100 Mbps、802.3z／802.3ab Gigabit、802.3ae 10 Gigabit、802.3x 全雙工與流量控制。

3. CSMA/CD 協定的五個概念

  • Carrier Sense：傳送前先聽通道是否有訊號，傳送中也持續聽（這是 CD 的關鍵）。
  • Deference：通道忙碌就延後傳送。
  • Collision：兩個以上站台同時傳送。
  • Backoff：碰撞後等待隨機時間再重傳。
  • Collision Window（Slot time）：來回傳播延遲加上一些載波偵測時間；802.3 定義為 51.2 μs。

補充Ethernet 屬於 1-persistent CSMA：通道一空就立刻傳。其他變形有 non-persistent（忙碌時隨機等一段再聽）與 p-persistent（通道空時以機率 p 傳送）。Slot time 本質是 512 bit times：10 Mbps 下為 51.2 μs，100 Mbps 下為 5.12 μs。

4. 碰撞偵測視窗 = 2a

最壞情況：A 要花 2a 才知道碰撞 動畫
上半是匯流排上的訊號（藍：A 的訊號；橘：B 的訊號；紫：兩者重疊＝碰撞）。下半是時空圖：橫軸是位置，縱軸是時間往下走。講義例子 a = 0.5、訊框傳輸時間 = 1。
  • 設 a = 傳播延遲（以一個訊框的傳輸時間為單位），講義例子 a = 0.5。
  • 時序：A 在 t0 開始送 → B 在訊號抵達前一瞬間（t0 + a − ε）開始送 → B 很快偵測到碰撞 → 碰撞訊號再傳回 A，A 在 t0 + 2a − ε 才偵測到。
  • 結論：最壞情況下，傳送端要花 2a 才能確定沒有碰撞，所以訊框傳輸時間必須 ≥ 2a，否則送完了還不知道有碰撞。

5. 碰撞處理與 BEBA

  • 碰撞訊號由實體層產生並通知 MAC。
  • Jam signal（collision enforcement）：送出 32 bits 的擾亂訊號，確保所有參與碰撞的站台都偵測得到。
  • Truncated Binary Exponential Backoff Algorithm（BEBA）：
    • n：目前已經歷的碰撞次數（n ≤ 16）
    • k = min(n, 10)：超過 10 次後不再加大（這就是 truncation）
    • r：隨機延遲時間，0 ≤ r < 2k（單位：slot time = 51.2 μs）
    • 第 16 次仍失敗 → 放棄並回報上層傳送失敗

BEBA 的缺點：Last-in First-out 效應。碰撞次數少的站台隨機範圍小，比較早重傳；已經等很久、碰撞很多次的站台隨機範圍大，反而更難搶到通道 → 不公平。在模擬器勾選「加入新站台 C」就能看到。

補充每個訊框之間至少要間隔 96 bit times（Interframe Gap，10 Mbps 下為 9.6 μs）。

6. IEEE 802.3 訊框格式

訊框欄位與長度計算器 互動
點選欄位看說明。
  • MAC frame size 從 DA 算到 FCS（不含 Preamble 與 SFD）。最小 64 bytes：用來和碰撞殘片區分；最大 1518 bytes：避免單一站台佔用頻寬太久。
  • 數字的由來（6 bytes 位址）：header + FCS = 6 + 6 + 2 + 4 = 18；最大 1500 + 18 = 1518；最小 64 − 18 = 46，資料不足 46 bytes 要用 PAD 補齊。
  • 補充64 bytes = 512 bits，在 10 Mbps 下剛好是 51.2 μs = 1 個 slot time，與「傳輸時間 ≥ 2a」的要求一致。

位址欄位

I/G 與 U/L 位元 圖解
  • I/G = 0 個別位址（unicast）；I/G = 1 群體位址（multicast／broadcast）。
  • U/L = 0 整體性位址（全球統一管理）；U/L = 1 區域性位址（自行管理）。
  • 補充實務上都用 48-bit 位址，即 MAC address；前 24 bits 為 IEEE 配發給廠商的 OUI。

8. 網路配置限制（10BASE5）

最大配置：5 個區段 圖解
依講義第 13 頁「Five segments, maximum」簡化重繪；精確連接方式請對照講義原圖。
  • 單一區段：同軸電纜最長 500 m，每區段最多 100 個收發器，收發器電纜最長 50 m。
  • 兩個區段：中間用訊號增益器連接。
  • 最大配置：5 個區段；兩個半訊號增益器之間的電纜最長 1000 m。
  • 講義提醒：Slot Time = 51.2 μs。這些限制都是為了讓最遠兩站之間的來回延遲不超過一個 slot time。
  • 補充常見記法是 5-4-3 規則：最多 5 個區段、4 個 repeater，其中只有 3 個區段可以接工作站。

11. CSMA/CD 為何在現代乙太網路消失

補充

  • 交換器（switch）＋全雙工（802.3x）後，每條線只有兩端且收發分開，不會碰撞，CSMA/CD 實際上不再運作。
  • 無線網路無法在傳送時偵測碰撞（自己的發射訊號會蓋過接收），所以 802.11 改用 CSMA/CA，這就是下一章的主題。

13. 考前自我檢查

  • 說明 slot time 51.2 μs 的意義，以及它與最小訊框 64 bytes 的關係
    Slot time 是碰撞視窗（來回傳播延遲＋載波偵測時間），也是 BEBA 的時間單位。64 bytes = 512 bits，在 10 Mbps 下傳完剛好 51.2 μs，保證送完之前一定能偵測到碰撞。
  • 解釋為何碰撞偵測視窗是 2a
    最壞情況是最遠端 B 在 A 的訊號抵達前一瞬間開始送；碰撞發生在 B 附近，碰撞訊號要再花 a 才回到 A，所以 A 在 t0 + 2a − ε 才知道。
  • 能寫出 BEBA 的 n、k、r 公式，並算出第 n 次碰撞的隨機範圍
    k = min(n, 10)，0 ≤ r < 2k（單位 slot time）。例如 n = 4：k = 4，r ∈ 0–15；n = 12：k = 10，r ∈ 0–1023；n > 16 放棄。
  • 說明 BEBA 的 LIFO 缺點
    碰撞多次的站台退避範圍大、等得久；新來的站台範圍小、很快重傳，反而先搶到通道，不公平。
  • 畫出 802.3 訊框格式並算出 1518 / 64 / 46 的由來
    Preamble 7｜SFD 1｜DA 6｜SA 6｜LEN 2｜LLC ≤1500｜PAD 0–46｜FCS 4。Header+FCS = 18；1500+18 = 1518；64−18 = 46。
  • 說明 I/G 與 U/L 位元的意義
    I/G：0 個別位址、1 群體位址。U/L：0 全球統一管理、1 區域自行管理。
  • 比較 10BASE5 / 10BASE2 / 10BASE-T / 10BROAD36
    10BASE5 粗同軸 500 m／100 站；10BASE2 細同軸 185 m／30 站；10BASE-T 雙絞線（標準 100 m 到 hub）；10BROAD36 75Ω 同軸、寬頻 DPSK、1800 m。
  • 分辨 IEEE 802.3 與 G.E. Thomas 的 Manchester 編碼
    IEEE 802.3：低→高 = 1、高→低 = 0。G.E. Thomas：高→低 = 1、低→高 = 0。
