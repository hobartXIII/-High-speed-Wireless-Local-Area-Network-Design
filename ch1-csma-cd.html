CH 1

🔌 IEEE 802.3 CSMA/CD（Ethernet）

來源：1CSMA_CD.pdf動畫與互動 4 個・圖解 6 張

補充CSMA/CD 是有線網路的協定，不是無線。它是 IEEE 802.3 乙太網路（Ethernet）的媒介存取控制（MAC）協定，規定共用同一條線的站台什麼時候可以傳送。無線區域網路（802.11）用的是 CSMA/CA。

  • 用在哪裡：多個站台共用同一條纜線的半雙工 Ethernet，例如早期的同軸電纜匯流排、接在 hub 上的雙絞線。
  • 名稱拆解：Carrier Sense 傳送前先聽線上有沒有人在傳；Multiple Access 多個站台共用同一條線；Collision Detection 傳送中持續監聽，一發現碰撞就停止、送 jam，再隨機退避重傳。
  • 為什麼只能用在有線：在線路上，站台可以一邊傳一邊比對線上的訊號，所以偵測得到碰撞。無線網路做不到：自己發射的訊號遠強於收到的訊號，傳送時聽不到別人；而且有隱藏節點，碰撞發生在接收端，傳送端根本不知道。所以 802.11 改用 CSMA/CA（Collision Avoidance），在第 2 章介紹。
  • 現況：現代乙太網路用 switch＋全雙工，每條線只有兩端而且收發分開，不會碰撞，CSMA/CD 實際上已不運作（見第 11 節）；但它是理解 802.11 CSMA/CA 的基礎。

1. 標準依據

  • IEEE 802.3：Carrier Sense Multiple Access with Collision Detection（CSMA/CD），即 Ethernet 的 MAC 與 PHY 標準。
  • 上層依據：IEEE 802.2 LLC；再往上是 IP、TCP、HTTP、FTP、SMTP 等高層協定。
  • 補充802.3 源自 DEC、Intel、Xerox 制定的 DIX Ethernet（Ethernet II）。差別在訊框第 13–14 byte：802.3 當作 Length，Ethernet II 當作 Type；數值 ≤ 1500 視為長度，≥ 1536（0x0600）視為 EtherType，所以兩種格式能共存。
  • 補充後續修訂：802.3u Fast Ethernet 100 Mbps、802.3z／802.3ab Gigabit、802.3ae 10 Gigabit、802.3x 全雙工與流量控制。

3. CSMA/CD 協定的五個概念（CSMA/CD Protocol）

  • Carrier Sense：傳送前（before transmission）先聽通道是否有訊號，傳送中（while transmission）也持續聽（這是 CD 的關鍵）。
  • Deference：通道忙碌就延後傳送（Defers transmission if channel is sensed busy）。
  • Collision：兩個以上站台同時傳送（Two or more stations transmitting simultaneously）。
  • Backoff：碰撞後等待隨機時間再重傳（Random delay after collision）。
  • Collision Window（Slot time）：來回傳播延遲加上一些載波偵測時間（Round-trip propagation delay time plus some carrier sense time）；802.3 定義為 51.2 μs。

補充Ethernet 屬於 1-persistent CSMA：通道一空就立刻傳。其他變形有 non-persistent（忙碌時隨機等一段再聽）與 p-persistent（通道空時以機率 p 傳送）。Slot time 本質是 512 bit times：10 Mbps 下為 51.2 μs，100 Mbps 下為 5.12 μs。

補充載波偵測＝偵測媒介上的能量

  • Carrier Sense 實際上是量測媒介上有沒有訊號能量（電壓變化）。講義流程圖的「線上有訊號？」判斷的就是這個。
  • 傳送中也持續量測能量，以此偵測碰撞：同軸電纜（10BASE5／10BASE2）上兩個站台同時傳送時，訊號互相疊加，收發器量到的平均直流電壓超過門檻，就判定碰撞並由 PLS 回報 MAC；10BASE-T 則是送出訊號的同時，接收線對也收到訊號，就判定碰撞。
  • Manchester 編碼每個 bit 中間都有跳變，只要有人在傳，線上就一定有持續的電壓變化，閒置與忙碌很容易分辨。
  • 訊號能量會隨距離衰減，距離太遠時遠端的訊號太弱，可能量不出碰撞；這也是區段長度受限制的原因之一。
  • 對照 802.11：無線也是用能量判斷通道是否忙碌（CCA 的 energy detection），但自己發射的能量遠大於收到的能量，所以只能在傳送前偵測，無法在傳送中偵測碰撞。

4. 碰撞偵測視窗 = 2a（Collision Detection Window for Baseband CSMA/CD）

最壞情況：A 要花 2a 才知道碰撞 動畫
上半是匯流排上的訊號（藍：A 的訊號；橘：B 的訊號；紫：兩者重疊＝碰撞）。下半是時空圖：橫軸是位置，縱軸是時間往下走。講義例子 a = 0.5、訊框傳輸時間 = 1。
  • 設 a = 傳播延遲（以一個訊框的傳輸時間為單位），講義例子 a = 0.5。
  • 時序：A 在 t0 開始送 → B 在訊號抵達前一瞬間（t0 + a − ε）開始送 → B 很快偵測到碰撞 → 碰撞訊號再傳回 A，A 在 t0 + 2a − ε 才偵測到。
  • ε 是什麼：一段極短的時間（可想成趨近 0）。B 不能等到 t0 + a 才送，因為那時已經聽到 A 的訊號，會依 Deference 延後；所以 B 最晚只能在 A 的訊號抵達「前一點點」開始，這一點點就是 ε。ε → 0 時，A 的等待時間趨近 2a，就是最壞情況；算界線時直接取 2a。
  • 補充實際的 ε 不會真的是 0：收發器需要一點時間才量得到線上的能量、確認有訊號。這就是講義把 Collision Window 定義為「來回傳播延遲＋一些 carrier sense 時間」的原因；802.3 再把 jam 與 repeater 延遲算進去，保守地定成 slot time = 51.2 μs。
  • 結論：最壞情況下，傳送端要花 2a 才能確定沒有碰撞，所以訊框傳輸時間必須 ≥ 2a，否則送完了還不知道有碰撞。

補充由 slot time 反推：最小訊框與網路長度

條件：訊框的傳輸時間 ≥ 來回傳播延遲 2τ（τ 為單程傳播延遲）。

  • 最小訊框長度：Lmin = R × 2τ = 2 × d × R ／ v（R：傳輸速率；d：最遠兩站的距離；v：訊號在線上的傳播速度，約 2×108 m/s）。
  • 802.3（10 Mbps）：slot time 51.2 μs = 512 bits = 64 bytes。理論上單程 τ 最多 25.6 μs，約可傳 5 km；扣掉 repeater、收發器電纜的延遲與 jam 時間後，標準只允許約 2500 m，保留安全餘裕。
  • 速率提高而最小訊框不變時，可容許的距離等比例變短：100 Mbps 的 slot time 只剩 5.12 μs，半雙工網路的直徑約 200 m。
  • 效率：常用近似式為 1 ／ (1 + 5a)，a = τ ／ 訊框傳輸時間。a 越小效率越高，也就是訊框越長、距離越短，效率越好。
✏️ 例題：1 Gbps、電纜 200 m、v = 2×108 m/s，最小訊框是多少？
τ = 200 ÷ (2×108) = 1 μs；2τ = 2 μs；Lmin = 109 × 2×10−6 = 2000 bits = 250 bytes。
這比 64 bytes 大得多，所以 Gigabit 半雙工把 slot time 加大到 512 bytes，短訊框用 carrier extension 補足。

5. 碰撞處理與 BEBA（CSMA/CD Collision Handling）

  • 碰撞訊號由實體層產生並通知 MAC（Collision Signal is generated by Physical layer）。
  • Jam signal（collision enforcement）：送出 32 bits 的擾亂訊號，確保所有參與碰撞的站台都偵測得到（To make sure that all stations involved in the collision will detect collision）。
  • Truncated Binary Exponential Backoff Algorithm（BEBA）：
    • n：目前已經歷的碰撞次數（number of collisions experienced）（n ≤ 16）
    • k = min(n, 10)：超過 10 次後不再加大（這就是 truncation）
    • r：隨機延遲時間（Random delay time），0 ≤ r < 2k（單位：slot time = 51.2 μs）
    • 第 16 次仍失敗 → 放棄並回報上層傳送失敗

BEBA 的缺點：Last-in First-out 效應。碰撞次數少的站台隨機範圍小，比較早重傳；已經等很久、碰撞很多次的站台隨機範圍大，反而更難搶到通道 → 不公平。（Stations with no or few collisions will have a better chance to transmit before stations that have waited longer）在模擬器勾選「加入新站台 C」就能看到。

補充每個訊框之間至少要間隔 96 bit times（Interframe Gap，10 Mbps 下為 9.6 μs）。

6. IEEE 802.3 訊框格式（IEEE 802.3 Frame Format）

訊框欄位與長度計算器 互動
點選欄位看說明。
  • MAC frame size 從 DA 算到 FCS（不含 Preamble 與 SFD）。最小 64 bytes：用來和碰撞殘片區分（Min 64 bytes to distinguish from collision）；最大 1518 bytes：避免單一站台佔用頻寬太久（Max 1518 bytes to prevent dominating bandwidth）。
  • 數字的由來（6 bytes 位址）：header + FCS = 6 + 6 + 2 + 4 = 18；最大 1500 + 18 = 1518；最小 64 − 18 = 46，資料不足 46 bytes 要用 PAD 補齊。
  • 補充64 bytes = 512 bits，在 10 Mbps 下剛好是 51.2 μs = 1 個 slot time，與「傳輸時間 ≥ 2a」的要求一致。

位址欄位

I/G 與 U/L 位元 圖解
  • I/G = 0 個別位址（unicast）（Individual Address）；I/G = 1 群體位址（multicast／broadcast）（Group Address）。
  • U/L = 0 整體性位址（全球統一管理）（Globally Administered Address）；U/L = 1 區域性位址（自行管理）（Locally Administered Address）。
  • 補充實務上都用 48-bit 位址，即 MAC address；前 24 bits 為 IEEE 配發給廠商的 OUI。

  • 檢查順序：講義流程圖為過短 → 位址 → 長度 → 檢查碼，先用成本低的條件把不需要的訊框過濾掉。
  • 長度錯誤的前提是 CRC 正確：若 CRC 也錯，代表傳輸途中就壞了，會歸為訊框錯誤或對齊錯誤，而不是長度錯誤。補充802.3 標準的接收程序也是先看 FCS，FCS 正確時才判定長度錯誤。
  • 802.3 MAC 只偵測錯誤、不負責更正：接收端不會回 ACK，也不會要求重送；錯誤的訊框直接丟棄，由上層負責恢復。這和之後 802.11 每個訊框都要 ACK 的做法不同。
  • 補充這些錯誤都會記錄在網卡的統計計數器中（例如 FCS errors、alignment errors、excessive collisions），可用來判斷線路品質或網路是否過度擁擠。
  • 補充其他常見態樣：訊框過長（超過 1518 bytes，俗稱 giant，常由故障網卡持續發送造成，稱為 jabber）；late collision（送出 64 bytes 之後才發生碰撞，代表網路長度超過規範，或雙工設定不一致）。

  • 單一區段：同軸電纜最長 500 m，每區段最多 100 個收發器，收發器電纜最長 50 m。
  • 兩個區段：中間用訊號增益器連接。
  • 最大配置：5 個區段；兩個半訊號增益器之間的電纜最長 1000 m。
  • 講義提醒：Slot Time = 51.2 μs。這些限制都是為了讓最遠兩站之間的來回延遲不超過一個 slot time。
  • 補充常見記法是 5-4-3 規則：最多 5 個區段、4 個 repeater，其中只有 3 個區段可以接工作站。

10. Manchester 編碼（Manchester Coding）

Manchester 波形產生器 互動
  • 每個 bit 的中間一定有電位跳變，用跳變方向表示 0 或 1。
  • 相鄰兩個相同位元（例如 1 1）時，位元邊界會多一次跳變，那次不代表資料（圖中以灰色虛線標示）。
規範高 → 低低 → 高
G.E. Thomas10
IEEE 802.301

兩種規範剛好相反，考試寫明依據哪一種。補充優點：自帶時脈（self-clocking），接收端可從跳變同步；缺點：訊號變化率是 bit rate 的兩倍，10 Mbps 需要 20 Mbaud 的頻寬。

補充時脈與資料怎麼合成一個訊號

把每個位元時間切成前半與後半：

  • 資料（Data，NRZ）：整個位元時間維持同一個值，1 整段高、0 整段低。
  • 時脈（Clock）：每個位元都是「前半高、後半低」，週期等於一個位元。
  • Manchester：把兩者做 XOR（互斥或）。
規範公式1 的波形0 的波形
IEEE 802.3Data ⊕ Clock低 → 高（↑）高 → 低（↓）
G.E. ThomasData ⊕ Clock 再反相高 → 低（↓）低 → 高（↑）
  • 驗算 IEEE 802.3（Clock 前半 1、後半 0）：資料 1 → 前半 1⊕1 = 0、後半 1⊕0 = 1，低 → 高 ✓；資料 0 → 前半 0⊕1 = 1、後半 0⊕0 = 0，高 → 低 ✓。
  • 兩種規範的波形互為反相，原理完全相同，只是約定不同。G.E. Thomas 是 1949 年最早提出的版本，IEEE 802.3 採用相反的定義。

IEEE 802.3 的第 3、4 位元都是 1，都必須從低電位開始；第 3 位元結束在高電位，所以兩者的邊界要先往下跳一次。上方產生器輸入任意位元即可對照。

補充位元中間 vs 位元邊界的跳變

跳變位置一定會有嗎代表資料嗎
位元中間每個位元都有是，方向就是資料（依規範判讀 ↑ 或 ↓）
位元邊界只有相鄰兩位元相同（1 1 或 0 0）時才有否，只是把電位拉回正確的起點

解碼時只看位元中間的跳變方向，邊界跳變忽略。

補充為什麼要把時脈混進去：self-clocking 與 Preamble

  • 不歸零編碼（NRZ）的問題：連續一長串 0 或 1 時線上沒有任何變化，接收端時鐘會漂移，數不清收了幾個位元。
  • Manchester 的解法：每個位元中間保證有跳變，接收端從跳變重建傳送端的時脈，不需要另拉一條時脈線。
  • 前導碼（Preamble） 1010…10：相鄰位元都不同，只有位元中間的跳變、沒有邊界跳變，等於一段乾淨的方波，接收端最容易鎖定時脈。
  • 訊框起始定界符（SFD） 10101011：最後的「11」產生第一次邊界跳變，接收端據此知道下一個位元開始是訊框內容（DA）。

補充代價與附帶好處

  • 頻寬加倍：最壞情況（全 1 或全 0）每半個位元就跳一次，10 Mbps 需要 20 Mbaud。100 Mbps 以上改用 4B/5B、8B/10B、64B/66B 等效率較高的編碼。
  • 直流平衡：每個位元都是一半高、一半低，平均電壓固定，可以用變壓器耦合（網卡上的隔離變壓器）。
  • 呼應第 3 節的能量偵測：單一站台傳送時平均直流電壓固定；兩站同時傳送時平均電壓明顯偏高，收發器就靠這點偵測碰撞。

  • 交換器（switch）＋全雙工（802.3x）後，每條線只有兩端且收發分開，不會碰撞，CSMA/CD 實際上不再運作。

13. 考前自我檢查

  • 說明 slot time 51.2 μs 的意義，以及它與最小訊框 64 bytes 的關係
    Slot time 是碰撞視窗（來回傳播延遲＋載波偵測時間），也是 BEBA 的時間單位。64 bytes = 512 bits，在 10 Mbps 下傳完剛好 51.2 μs，保證送完之前一定能偵測到碰撞。
  • 解釋為何碰撞偵測視窗是 2a
    最壞情況是最遠端 B 在 A 的訊號抵達前一瞬間開始送；碰撞發生在 B 附近，碰撞訊號要再花 a 才回到 A，所以 A 在 t0 + 2a − ε 才知道。
  • 能寫出 BEBA 的 n、k、r 公式，並算出第 n 次碰撞的隨機範圍
    k = min(n, 10)，0 ≤ r < 2k（單位 slot time）。例如 n = 4：k = 4，r ∈ 0–15；n = 12：k = 10，r ∈ 0–1023；n > 16 放棄。
  • 說明 BEBA 的 LIFO 缺點
    碰撞多次的站台退避範圍大、等得久；新來的站台範圍小、很快重傳，反而先搶到通道，不公平。
  • 說明碰撞是怎麼被偵測出來的
    量測媒介上的能量：同軸電纜上兩個訊號疊加，平均直流電壓超過門檻就判定碰撞；10BASE-T 是送出時接收線對也收到訊號。無線因為自己發射的能量太強，只能在傳送前偵測。
  • 用 Lmin = 2dR／v 算最小訊框
    例：1 Gbps、200 m、v = 2×108 m/s → τ = 1 μs，2τ = 2 μs，Lmin = 2000 bits = 250 bytes。
  • 算 BEBA 第 n 次碰撞後的平均等待與再撞機率
    平均 (2k − 1)／2 個 slot，再撞機率 1／2k，k = min(n, 10)。例：n = 3 → 3.5 slot = 179.2 μs，機率 1/8。
  • 比較 Hub 與 Switch 的碰撞網域、廣播網域
    Hub：所有埠同一個碰撞網域、一個廣播網域，半雙工需 CSMA/CD。Switch：每埠一個碰撞網域、仍是一個廣播網域（要 router／VLAN 才能切開），全雙工不需 CSMA/CD。
  • 畫出 802.3 訊框格式並算出 1518 / 64 / 46 的由來
    Preamble 7｜SFD 1｜DA 6｜SA 6｜LEN 2｜LLC ≤1500｜PAD 0–46｜FCS 4。Header+FCS = 18；1500+18 = 1518；64−18 = 46。
  • 說明 I/G 與 U/L 位元的意義
    I/G：0 個別位址、1 群體位址。U/L：0 全球統一管理、1 區域自行管理。
  • 比較 10BASE5 / 10BASE2 / 10BASE-T / 10BROAD36
    10BASE5 粗同軸 500 m／100 站；10BASE2 細同軸 185 m／30 站；10BASE-T 雙絞線（標準 100 m 到 hub）；10BROAD36 75Ω 同軸、寬頻 DPSK、1800 m。
  • 分辨 IEEE 802.3 與 G.E. Thomas 的 Manchester 編碼
    IEEE 802.3：低→高 = 1、高→低 = 0。G.E. Thomas：高→低 = 1、低→高 = 0。
  • 用 Data ⊕ Clock 畫出一串位元的 Manchester 波形，並指出哪些是邊界跳變
    IEEE 802.3 = Data XOR Clock（Clock 前半 1、後半 0），G.E. Thomas 再反相；只有相鄰位元相同時才有邊界跳變，解碼只看位元中間的跳變。
