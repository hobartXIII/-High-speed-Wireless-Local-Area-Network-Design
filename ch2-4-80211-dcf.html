⏱️ IEEE 802.11 DCF 存取機制（CSMA/CA）

來源：2-4 CSMA_CA | iLearning 3.pdf（投影片標題「802.11 Architecture」，NCHU CSE CSMA/CA p.1–35）動畫與互動 9 個・圖解 4 張
PDF 共 33 頁，對應投影片第 1–35 頁；第 12、18 頁不在 PDF 中 待確認。本章接續 2-3「WEP 與 MAC 訊框格式」：2-3 講訊框長什麼樣子，這一章講站台什麼時候可以送。

DCF（分散式協調功能）就是 802.11 的 CSMA/CA：沒有裁判，每個站台自己「先聽媒介 → 閒置 DIFS → 隨機退避倒數 → 送出 → 等 ACK」，靠同一套規則輪流用同一個頻道。

  • DCF：802.11 最基本的存取方法，所有站台都必須實作；PCF 是蓋在 DCF 上面的選用輪詢機制。
  • IFS 決定優先權：SIFS ＜ PIFS ＜ DIFS ＜ EIFS，等得越短越優先（ACK／CTS 用 SIFS，PCF 用 PIFS，一般資料用 DIFS）。
  • 退避：Backoff = Random(0..CW) × Slot time；媒介忙時計時器凍結，失敗一次 CW 加倍（15 → 31 → … → 1023）。
  • RTS/CTS＋NAV：用 Duration 預約媒介，解決 hidden node；超過 RTS_Threshold 才用，廣播／群播不用、也不回 ACK。

5. DCF 的功能（p.9–11）（Distributed Coordination Function）

DCF 是 802.11 預設、所有站台都必須實作的媒介存取方法：沒有中央控制者，每個站台各自用「載波感測＋IFS＋隨機退避＋ACK」決定什麼時候可以送，也就是 CSMA/CA。

  • 名字拆開看：Distributed＝沒有 AP 當裁判，每個站台自己判斷；Coordination＝大家遵守同一套等待規則，所以不必溝通也能錯開；Function＝它是 MAC 層的一個功能（PCF 才由 AP 這個 Point Coordinator 輪詢）。
  • 送一個訊框的五步：
    1. 先聽：實體載波感測（CCA）與虛擬載波感測（NAV）都說閒置，媒介才算閒置。
    2. 等 DIFS：媒介持續閒置 DIFS；若封包到達時媒介已閒置超過 DIFS，可直接送。
    3. 隨機退避：從 [0, CW] 抽一個數 × Slot time 倒數；媒介一忙就凍結，閒置 DIFS 後接著數。
    4. 送出：數到 0 就送（長訊框可先 RTS/CTS 預約）。
    5. 等 ACK：接收端隔 SIFS 回 ACK 才算成功；沒收到 ACK → CW 加倍、重來，超過重試上限就丟棄。
  • 為什麼要這樣：無線站台送的時候聽不到碰撞（不能 CD），只能事先避免（CA）、事後靠 ACK 確認。
  • 補充比喻：沒有主持人的會議——先確認沒人在講話，再各自默數一個隨機秒數，先數完的人發言，對方點頭（ACK）才算講完；兩人同時開口就各自把數字範圍放大再來一次。
  • 七項功能（Features）：IFS、隨機退避、正向 ACK、實體載波感測、虛擬載波感測（在多速率環境仍有效）、選用 RTS/CTS（由 RTS_Threshold 控制）、選用分段（由 Fragmentation_Threshold 控制）。
  • 自動共享媒介：相同或不同的 PHY 都能透過 CSMA/CA 加上「媒介忙碌之後的隨機退避」共用媒介。
  • 正向 ACK：所有單播（directed）流量都要立即回 ACK；沒收到 ACK，由傳送端安排重傳。
  • 虛擬載波感測：在真正的資料訊框前交換小的 RTS、CTS 訊框（帶 Duration 欄位），把「媒介會忙多久」散播出去。
    • 只用於單播（Unicast only, not used in multicast/broadcast）。
    • 由 RTS_Threshold 控制：payload 長度低於門檻就不加 RTS/CTS。
  • 多速率：所有站台都必須能接收基本速率組內任一速率的訊框，並至少能用其中一種速率傳送，所以虛擬載波感測在多速率環境仍然有效。補充控制訊框用基本速率送，大家都解得出 Duration。
  • 兩種載波感測（p.11）：
    • 實體：由 PHY 提供，也就是空閒頻道評估（Clear Channel Assessment, CCA）。
    • 虛擬：由 MAC 提供，叫做網路配置向量（Network Allocation Vector, NAV），依 RTS/CTS 宣告的 Duration 預測未來的流量。
  • MAC 層確認：成功收到訊框後立即回 ACK，間隔是 SIFS；要回 ACK 的訊框類型：Data、Poll、Request、Response。沒收到 ACK 就表示出錯（The lack of an ACK frame means that an error has occurred）。

💡 講義提問（p.11）：為什麼 Ethernet 不用 ACK 訊框？

有線網路可以「邊送邊聽」，碰撞會被 CSMA/CD 偵測到並立刻重送，而且銅線／光纖的位元錯誤率很低，交給上層（TCP）處理就夠了。無線則不行：自己的發射訊號比收到的訊號強太多，送的時候聽不到碰撞（無法 CD）；hidden node 讓傳送端根本感測不到干擾；加上無線錯誤率高，所以必須由接收端用 ACK 明確告訴傳送端「收到了」。

⚠️ 講義勘誤（p.11、p.25）

原文：「Net Allocation Vector (NAV)」
正確：「Network Allocation Vector (NAV)」

理由：IEEE 802.11 標準用語是 Network Allocation Vector；2-3 講義也用 Network。

6. 訊框間隔 IFS（p.13–15）（Inter-Frame Space）

  • 定義：媒介變成空閒後，站台必須先等的一段時間；等越短的越優先，所以 IFS 就是優先權（Three different IFS's are defined to provide priority levels）。
IFS誰用講義說明
SIFS（Short IFS）ACK、CTS、回應輪詢的站台；PC 在 CFP 內送任何訊框最短，最高優先：一次交換中的「回應」不用跟別人搶
PIFS（PCF IFS）只有 PCFPC 偵測到媒介空閒 PIFS 後就能送 CFP 訊框（CF-Burst 開始與期間）
DIFS（DCF IFS）DCF 送非同步 MPDU偵測到媒介空閒 DIFS，且不在退避期間，就能送
EIFS（Extended IFS）上一個收到的訊框有錯時最長，見下方
  • 新增的 IFS：11e 的 AIFS（Arbitrated IFS）、11n 的 RIFS（Reduced IFS）、802.11-2016 的 SBIFS／BRPIFS／MBIFS／LBIFS（講義：check DIY）。
  • 時間關係（p.14 圖）：PIFS = SIFS + 1 slot、DIFS = SIFS + 2 slots，DIFS 之後才是第一個退避時槽（First backoff slot）。
  • p.14 圖中的元件：D1 = aRxRFDelay + aRxPLCPDelay；D2 = D1 + 空中傳播時間；Rx/Tx = aRxTxTurnaroundTime；M1 = M2 = aMACPrcDelay；CCAdel = aCCATime − D1。
  • EIFS（p.15）
    • 從 PHY 指出「收到錯誤訊框後媒介已空閒」開始計時，不管虛擬載波感測。
    • 目的：給別的站台足夠時間，對「這個站台收錯的那個訊框」回 ACK，再讓這個站台開始傳送。
    • EIFS = aSIFSTime + (8 × ACKsize) + aPreambleLength + PLCPHeaderLength + DIFS，ACKsize 以 1 Mbps 計算。
IFS 尺規：誰先能送？ 互動

7. 隨機退避與二元指數退避（p.16–17）（Random Backoff Time）

  • 送非同步 MPDU 之前，先用載波感測判斷媒介狀態。
  • 媒介忙：等到偵測到 DIFS 的空閒，再產生一段隨機退避時間，額外延後（化解競爭）。

8. 基本存取協定（p.19–21）（Basic Access Protocol）

  • 特點（p.19）
    • 用 DCF 有效率地共享媒介，不受重疊限制；以 CSMA/CA 為基礎，載波感測來自 PHY 的 CCA。
    • 對干擾強健：單播用 CSMA/CA＋ACK，MAC 層就能重傳；廣播用 CSMA/CA（沒有 ACK）。
    • 參數化使用 RTS/CTS，提供虛擬載波感測，對抗 hidden node；Duration 由傳送端與接收端分別透過 RTS、CTS 散播。
    • 有分段，因應不同 PHY 的特性；訊框格式支援 Infrastructure、Ad-Hoc 與 WDS。
  • CSMA/CA 解說（p.20）
    • 媒介空閒超過 DIFS → 直接送（Free access when medium is free longer than DIFS）。
    • 否則延後（Defer），等媒介空閒 DIFS 後進入競爭視窗，選一個時槽，媒介空閒時才遞減退避值，歸零就送。
    • 在最需要的地方降低碰撞機率：大家都在等媒介空閒的那一刻最容易撞，所以這時才隨機退避。
    • 退避演算法在高負載下穩定：重傳時視窗指數成長；只有媒介空閒時退避計時器才前進。
    • 固定的優先權等級：讓立即回應（ACK、CTS）與 PCF 能共存。
  • CSMA/CA＋ACK 協定（p.21）
    • 依載波感測延後：PHY 的 CCA 加上虛擬載波感測（NAV）狀態。
    • 媒介空閒超過 DIFS 直接存取，否則延後並退避。
    • 單播的接收端在 CRC 正確時立即回 ACK。
    • 沒收到 ACK → 隨機退避後重傳（有次數上限）。
CSMA/CA＋ACK 時序 動畫
依講義第 20、21 頁重繪（時間比例為示意）。Other 在 Data 期間由 CCA 判斷媒介忙；Data 的 Duration 再讓它的 NAV 蓋住 SIFS＋ACK。

9. DCF 的缺點：額外負擔（p.22–23）（Drawback of DCF）

  • DCF 在 PHY 與 MAC 上產生大量額外負擔：前導碼（Preamble）、PHY 與 MAC 標頭、退避、IFS、ACK。
  • 講義 p.22 的數字：DIFS 34 µs、Backoff 9 µs × [0, CW]、PLCP Preamble 16 µs、PLCP Header ≥ 4 µs、MAC Header ≥ 30 octets、FCS 4 octets、SIFS 16 µs、ACK ≥ 24 µs。補充這組數字是 802.11a OFDM。
  • 吞吐量效率（p.23 圖，23 µs Slot time）：負載增加時吞吐量先上升後持平，過載時仍穩定，能支援突發（bursty）流量。576 bytes 訊框最高（約 195 KByte/s），60% 短＋40% 長次之（約 160），64 bytes 最低（約 88）：訊框越短，固定額外負擔佔比越大。
一筆傳送的時間都花在哪？ 互動
補充單一站台、沒有碰撞、退避取平均 CWmin/2 = 7.5 slots。OFDM 訊框時間 = 20 + 4 × ⌈(16 + 8L + 6) ÷ NDBPS⌉ µs，NDBPS = 4 × 速率；MAC Header 24 + FCS 4 bytes。下方曲線是吞吐量對 payload 大小。

待確認 待確認

1. p.22「MAC Header ≥ 30 octets」：3 位址標頭是 24 octets、4 位址是 30 octets；補充QoS 資料訊框標頭 26 ＋ FCS 4 也是 30。講義的 30 指哪一種請對照上課說明。

2. p.23「23 usec Slot time」：FHSS 50、DSSS 20、OFDM 9 µs，補充沒有 PHY 用 23 µs，可能是早期模擬參數。

10. Hidden Node 與 RTS/CTS（p.24–26）（Hidden Node Problem／Provisions）

  • 問題：競爭媒介的傳送端可能互相聽不到（may not "Hear each other"）：兩個 STA 都聽得到 AP，彼此卻聽不到，載波感測失效，兩邊同時送就在 AP 撞在一起。
  • 解法：傳送端與接收端先交換獨立的控制訊框 RTS／CTS，為後續的資料存取預約媒介（Reserve the Medium）；Duration 會散播到傳送端與接收端兩邊。
  • Hidden Node 的配套（p.25）
    • RTS、CTS 的 Duration 欄位散播「媒介預約」資訊，存進 NAV。
    • NAV 或 CCA 任一個表示媒介忙，就延後。
    • RTS/CTS 是選用的，但一定要實作（optional but must be implemented）。
    • 每個站台用 RTS_Threshold 參數控制要不要用：限制短訊框的額外負擔（講義例：200 bytes）。

11. DCF 存取程序（p.27–28）（DCF Access Procedure）

  • 退避程序（p.27）
    • 先選好退避時間。媒介忙時計時器凍結（frozen），只有空閒時才遞減（每次空閒超過 DIFS 才恢復倒數）。
    • 計時器到 0 就送。
    • 剛送完一個訊框、佇列裡還有下一個的站台，也必須執行退避（公平性考量），不能連續霸佔。
    • 整體趨向先到先服務（FCFS）的公平存取：上一輪沒輪到的站台保留剩餘退避值，下一輪通常比新來的先到 0。
五個站台的退避：凍結與恢復 動畫

  • RTS/CTS 復原程序與重傳上限（p.28）
    • 送出 RTS 後，若在 CTS_Timeout（T1）內沒收到 CTS，就產生新的 RTS（CW 加倍），直到 RTS_Re-Transmit_Counter 到達 RTS_Re-Transmit_Limit。

    • 每個 MSDU／MMPDU 有兩個計數器：短重傳計數（short retry count）給長度 ≤ RTS_Threshold 的訊框，長重傳計數（long retry count）給 ＞ RTS_Threshold 的訊框；兩者獨立遞增、獨立歸零。

12. 分段（p.29–33）（Fragmentation）

  • 控制頻道（p.29）：站台搶到頻道後會連續送完所有分段，段與段之間只隔 SIFS，別人插不進來；直到以下任一情況才停：
    • MSDU 的所有分段都送完；
    • 某段沒收到 ACK；
    • 碰到駐留時間（dwell time）邊界，不能再送（補充FHSS 跳頻時）。
  • 沒收到 ACK → 之後依退避演算法只重傳那一段，重傳時要重新在競爭視窗中競爭。
  • RTS/CTS 搭配分段（p.30–31）
    • RTS/CTS 的 Duration 只涵蓋第一個分段與它的 ACK。
    • Data 與 ACK 的 Duration 涵蓋「下一個分段＋它的 ACK」：每個分段與 ACK 都扮演虛擬的 RTS 與 CTS，一路把 NAV 往後延。
    • 最後一個分段與 ACK 的 Duration 設為 0（講義）。
    • ACK 沒收到（最壞情況）：只聽得到目的端的站台不會更新 NAV，可以存取頻道；聽得到來源端的站台在 Fragment 1 的 NAV 到期後可以存取；來源端也必須等 NAV（Fragment 1）到期才能重新競爭。
  • Fragmentation (1/2)（p.32）：一串個別確認的分段，只用於單播；某段沒 ACK → 隨機退避後重傳該段；Data 與 ACK 的 Duration 設定 NAV 作為媒介預約。
  • Fragmentation (2/2)（p.33）
    • 除最後一段可以較短，其他分段的長度都一樣。
    • 分段長度不可超過 aFragmentationThreshold，除非該 MPDU 有用 WEP（因為會多出 IV 與 ICV）。
    • 同一個 MSDU／MMPDU 的所有分段 Sequence Number 相同；依 Fragment Number 由小到大依序送（從 0 開始，每次加 1）。
    • More Fragments 位元標示最後（或唯一）一段。

待確認（p.30） 待確認

講義寫「最後一個 Fragment 與 ACK 的 Duration 設為 0」。補充依 IEEE 802.11 標準，最後一個分段的 Duration = SIFS + ACK 時間（還要保護自己的 ACK），只有最後的 ACK 是 0。請對照上課說明。

13. 重組（p.34）（Defragmentation）

  • 每個分段的標頭帶有目的端重組 MSDU／MMPDU 需要的資訊：Frame type、傳送端位址、目的位址、Sequence Control、More Fragments 指示。
  • 若用了 WEP，先解密再重組（decrypted before the defragmentation）。
  • 每個站台對每個 MSDU／MMPDU 維護一個接收計時器（Receive Timer）；沒維護計時器的話，該 MSDU 的分段全部丟棄。
  • 接收計時器超過 aMaxReceiveLifetime，已收到的分段全部丟棄。

14. 廣播與群播（p.35）（DCF – Broadcast and multicast）

  • 沒有 PCF 時，STA 送 ToDS = 0 的廣播／群播 MPDU：只用基本存取程序；不管多長都不用 RTS/CTS，也不會收到 ACK。
  • STA 送 ToDS = 1 的廣播／群播 MPDU：要遵守 RTS/CTS 規則，因為這個 MPDU 是送給 AP 的（單播給 AP，會收到 ACK）。
  • 廣播／群播沒有 MAC 層復原，除了 ToDS = 1 的那些。
  • 廣播／群播訊息會被散播到整個 BSS，發送者自己也會收到；所以每個站台都要濾掉「來源位址是自己」的廣播／群播。
  • 廣播／群播 MSDU 會傳遍整個 ESS。

⚠️ 講義勘誤（p.35）

原文：「This no MAC-level recovery on broadcast or multicast frames…」
正確：「There is no MAC-level recovery on broadcast or multicast frames…」

理由：原句缺動詞，應是 There is 的筆誤。

17. 複習問題

觀念題

1. DCF 與 PCF 的關係是什麼？為什麼 PCF 能搶到媒介？
DCF 是 802.11 的基本存取方法（CSMA/CA），所有站台都必須實作；PCF 是選用的無競爭存取方法，建在 DCF 之上，由 AP 上的點協調器輪詢。PC 只要等 PIFS（= SIFS + 1 slot），比 DCF 站台要等的 DIFS（= SIFS + 2 slots）短，所以媒介一空閒，PC 一定比一般站台先送，就能「搶」到媒介開始無競爭期。
2. 為什麼 ACK 與 CTS 用 SIFS？如果改用 DIFS 會發生什麼事？
SIFS 最短，回應的站台一定比任何正在等 DIFS 的站台先送，整個 Data–ACK（或 RTS–CTS–Data–ACK）交換不會被打斷。若改用 DIFS，別的站台可能退避剛好到 0、在 ACK 之前搶先傳送，ACK 被撞掉，傳送端以為失敗而重傳，浪費頻寬。
3. 退避計時器為什麼在媒介忙時「凍結」而不是重新抽？
凍結保留剩餘值，等越久的站台剩餘值越小，下一輪更容易先到 0，整體趨向先到先服務（FCFS）的公平；若每次都重抽，運氣不好的站台可能一直抽到大數字而餓死。可以在第 11 節的動畫看 B、D 的紅色剩餘值。
4. Hidden node 是什麼？RTS/CTS 怎麼解決？為什麼廣播不能用 RTS/CTS？
兩個 STA 都在 AP 範圍內但彼此聽不到，載波感測失效，同時送就在 AP 碰撞。RTS/CTS 讓接收端（AP）用 CTS 把 Duration 廣播給它範圍內的所有站台，hidden node 聽到 CTS 就設 NAV 不送。廣播有很多接收者，不可能讓所有人都回 CTS（會互撞），所以廣播／群播只用基本存取，也沒有 ACK。
5. 什麼時候用 EIFS？為什麼要比 DIFS 長？
站台收到錯誤的訊框後（PHY 指出媒介空閒），要等 EIFS 而不是 DIFS。因為這個訊框可能是別人的 Data，它的接收端收到正確的話會在 SIFS 後回 ACK；EIFS 多等了一個以 1 Mbps 送的 ACK 時間，避免撞掉那個 ACK。

計算題

6. 802.11b（SIFS 10 µs、Slot 20 µs、CWmin 31、CWmax 1023），算 PIFS、DIFS、初次的平均與最大退避時間，以及第 3 次重傳時的 CW。
PIFS = 10 + 20 = 30 µs；DIFS = 10 + 2 × 20 = 50 µs。初次平均退避 = 31 ÷ 2 × 20 = 310 µs；最大 = 31 × 20 = 620 µs。CW：31 → 63 → 127 → 255，第 3 次重傳時 CW = 255。
7. 802.11a 54 Mbps、RTS/CTS 啟用、Data 248 µs、RTS／CTS／ACK 各 24 µs、SIFS 16 µs。算 RTS、CTS、Data 的 Duration。
RTS = SIFS + CTS + SIFS + Data + SIFS + ACK = 16 + 24 + 16 + 248 + 16 + 24 = 344 µs。CTS = 344 − 16 − 24 = 304 µs。Data = SIFS + ACK = 16 + 24 = 40 µs。
8. 18 Mbps 設為基本速率、48 Mbps 設為非基本，Supported Rates 裡各編成什麼？
18 ÷ 0.5 = 36 = 0x24，基本速率 bit 7 設 1 → 0x24 + 0x80 = 0xA4。48 ÷ 0.5 = 96 = 0x60，非基本 → 0x60。可以用第 2 節的編碼器驗證。

情境應用題

9. 大型會議廳裡一台 AP 服務很多筆電，彼此距離遠、常常互相聽不到，使用者抱怨很慢。RTS_Threshold 該怎麼調？
互相聽不到代表 hidden node 多，碰撞會發生在長的 Data 上，代價大。把 RTS_Threshold 調低（例如講義的 200 bytes），讓較長的訊框先 RTS/CTS：碰撞只發生在 20 bytes 的 RTS，損失小，而且 CTS 讓 hidden node 設 NAV。短訊框仍不用 RTS/CTS，避免額外負擔（講義 p.26：Mixed 的效率最好）。
10. 11g AP 的 BSS 裡加入一台舊的 11b 印表機，AP 的 ERP 資訊元素會怎麼變？11g 筆電的傳送方式會怎麼變？
AP 把 NonERP_Present（b0）設 1，通常也把 Use_Protection（b1）設 1。11g 筆電之後用 ERP-OFDM 速率送資料前，要先用保護機制：用 11b 聽得懂的 DSSS 速率送 CTS（CTS-to-self）或 RTS/CTS，讓印表機設 NAV，再用 OFDM 送資料。吞吐量會因此下降。

  3. ERP：b0 NonERP_Present、b1 Use_Protection；Non-ERP = 11b；保護 = 先送 CTS 設 NAV。
  4. DCF = CSMA/CA，所有站台必備；PCF 建在 DCF 上、AP 輪詢、用 PIFS；superframe = CFP + CP。
  5. SIFS（ACK、CTS）＜ PIFS = SIFS + slot ＜ DIFS = SIFS + 2 slot ＜ EIFS。
  6. EIFS = SIFS + 8 × ACK ÷ 1 Mbps + Preamble + PLCP Header + DIFS（11b：364 µs）。
  7. Backoff = Random[0, CW] × slot；忙時凍結、空閒才倒數；失敗 CW 加倍（15 → … → 1023；DSSS 31、IR 63 起跳）。
  8. 單播一定回 ACK（SIFS 後）；沒 ACK = 失敗；短／長 retry count 以 RTS_Threshold 區分。
  9. RTS/CTS：單播且超過 RTS_Threshold 才用；Duration → NAV；NAV 或 CCA 忙就延後；解決 hidden node。
  10. 分段：同 Seq、Frag 號遞增、SIFS 連發；Data／ACK 的 Duration 涵蓋下一段＋ACK；廣播 ToDS = 0 無 RTS/CTS、無 ACK、無 MAC 復原。

20. 考前自我檢查

  • 寫出資訊元素的格式，背出 SSID、Supported Rates、TIM 等的 Element ID
    Element ID（1）＋ Length（1）＋ Information；SSID 0、Supported Rates 1、FH 2、DS 3、CF 4、TIM 5、IBSS 6、Country 7、Legacy Indication 8、Challenge Text 16。
  • 把某個速率編成 Supported Rates 的 octet
    速率 ÷ 0.5 Mbps 放低 7 bits；屬於 BSSBasicRateSet 時再加 0x80。例：1 Mbps 基本 = 0x82。
  • 說明 ERP 的 b0、b1 與保護機制
    b0 NonERP_Present：BSS 內有沒有 11b 站台；b1 Use_Protection：用 OFDM 前要不要先保護。保護 = 先用 CTS 設所有站台的 NAV。
  • 畫出 DCF／PCF 架構圖並說明 superframe
    PHY 上是 DCF（競爭服務，PCF 的基礎），DCF 上是 PCF（無競爭服務）；superframe 開頭是 PCF 的無競爭期，接著是 DCF 的競爭期。
  • 列出 DCF 的七項功能
    IFS、隨機退避、正向 ACK、實體載波感測、虛擬載波感測、選用 RTS/CTS、選用分段。
  • 說出 SIFS、PIFS、DIFS、EIFS 各給誰用，並算出 PIFS、DIFS
    SIFS：ACK、CTS、輪詢回應；PIFS = SIFS + slot：PC；DIFS = SIFS + 2 slots：一般資料；EIFS：收錯後。11b：30、50 µs；11a：25、34 µs。
  • 寫出 EIFS 公式並算出 11b 的 364 µs
    10 + 8 × 14（1 Mbps）+ 144 + 48 + 50 = 10 + 112 + 192 + 50 = 364 µs。
  • 寫出 Backoff 公式、CW 加倍規則與各 PHY 的範圍
    Random[0, CW] × slot；CWi = min(2i(CWmin+1) − 1, CWmax)；FHSS 15、DSSS 31、IR 63、ERP（＞20 Mb/s）15、11n 15，CWmax 都是 1023。
  • 畫出 Src／Dest／Other 的 CSMA/CA＋ACK 時序
    Src：DIFS → Data；Dest：SIFS → Ack；Other：Data＋ACK 期間 Defer Access，之後 DIFS → Contention Window（Backoff after Defer）→ Next MPDU。
  • 說明退避計時器何時凍結、何時恢復，以及為什麼公平
    媒介忙時凍結；媒介空閒 DIFS 後恢復倒數。剩餘值保留，等越久越先到 0，趨向 FCFS；剛送完的站台也要退避。
  • 解釋 hidden node，畫出 RTS／CTS／Data／ACK 與 NAV(RTS)、NAV(CTS)
    兩站彼此聽不到但都聽得到 AP。Src：DIFS → RTS；Dest：SIFS → CTS；Src：SIFS → Data；Dest：SIFS → Ack。Other 從 RTS 設 NAV(RTS)、從 CTS 設 NAV(CTS)，到 ACK 結束後再 DIFS、退避。
  • 算出 RTS、CTS、Data 的 Duration 值
    RTS = 3 SIFS + CTS + Data + ACK；CTS = RTS 的值 − SIFS − CTS；Data = SIFS + ACK；ACK = 0。
  • 說明 short／long retry count、CTS_Timeout、ACK_Window
    ≤ RTS_Threshold 用 short、＞ 用 long，獨立計數；T1 內沒 CTS → 重送 RTS 且 CW 加倍；T3 內沒 ACK → 同樣退避重傳；到 limit 就丟棄。
  • 說明分段規則、RTS/CTS＋分段時 NAV 的延伸，以及 ACK 遺失時誰可以存取頻道
    同 Seq、Frag 號從 0 遞增、除最後一段等長、不超過 aFragmentationThreshold（WEP 除外）、SIFS 連發；Data／ACK 的 Duration 涵蓋下一段＋ACK。ACK 遺失：只聽得到目的端的站台馬上可存取；聽得到來源端的站台等 Fragment 的 NAV 到期；來源端也要等到期再競爭。
  • 說出廣播／群播在 ToDS = 0 與 ToDS = 1 時的差異
    ToDS = 0：基本存取、不用 RTS/CTS、沒 ACK、沒 MAC 復原；ToDS = 1：送給 AP 的單播，照 RTS/CTS 規則、有 ACK。發送者自己也會收到，要濾掉來源是自己的。
