🔋 IEEE 802.11 PCF 與 MAC 管理

PDF 共 32 頁，對應投影片第 1–32 頁。本章接續 2-4「DCF 存取機制」：2-4 講大家怎麼搶媒介（DCF），這一章前半講 AP 怎麼點名（PCF），後半講站台怎麼對時、睡覺、找網路、換 AP（MAC 管理層）。

PCF 是 AP 當「點名老師」的選用存取方式：在超級訊框開頭的無競爭期（CFP）裡，AP 用 PIFS 搶到媒介、一個一個輪詢站台；MAC 管理層則靠 Beacon 裡的時間戳記讓全 BSS 對時，站台才能放心睡覺、準時醒來收 TIM，並透過掃描、Association、Reassociation 加入網路與漫遊。

  • PCF：Point Coordinator 在 AP；CFP 開頭等 PIFS（比 DIFS 短）就送 Beacon，之後每個訊框只隔 SIFS，DCF 站台插不進來；用 CF-Poll 點名、CF-Ack 捎帶確認、CF-End 結束並重設 NAV。
  • CFP 時序：CFP 每隔「若干個 DTIM 間隔」出現一次；Beacon 被延後時 CFP 會縮短（foreshortened），但最晚在 TBTT + CFPMaxDuration 結束。
  • 同步（TSF）：AP 的 Beacon 帶時間戳記，大家照著校正；Beacon 永遠排在 TBTT，不是「上一次 Beacon 之後再算」。
  • 省電：AP 替睡著的站台緩衝資料，Beacon 的 TIM 告訴它「你有信」，站台醒來送 PS-Poll 取件；廣播／群播只在 DTIM 之後送。IBSS 改用 ATIM window 互相通知。
  • 掃描與漫遊：被動掃描聽 Beacon、主動掃描送 Probe Request；選好 AP 後 Association；訊號變差就用 Reassociation 換到新 AP。

    • SF 由無競爭期（Contention Free period, CF／CFP）與競爭期（Contention Period, CP）組成。
    • SF 的長度是可管理的參數；CF period 的長度每個 SF 都可以不同。

3. PCF Burst（p.4）（Contention Free Burst）

  • CF-Burst 由 CF-Down 訊框中的 Polling bit 啟動：AP（PC）送下行訊框時把 CF-Poll 位元設起來，就是在點名。
  • 站台收到 CF_Poll 要立即回應（Immediate response）。
  • 其他站台要維持 NAV，保護 CF 流量不被打斷。
  • 回應的長度可以不固定（variable length）。
  • AP 送出最後的 CF_End 訊框來重設 NAV（Reset NAV）。
  • 標頭裡的「ACK Previous Frame」位元：確認上一個訊框，搭便車（piggyback）送出，不必另外送 ACK。
  • 講義的圖：CFP repetition interval 開頭，媒介忙完等 PIFS，AP 送 D1，STA 隔 SIFS 回 U1；接著 D2／U2、D3（No Up：這個站台沒回）、D4／U4，最後 CF_End 重設 NAV，後面是 Contention Period（至少要留 Min Contention Period）。Dx = AP 送的訊框、Ux = 站台送的訊框。

5. CFP 結構與時序、Beacon 產生（p.7–9）（CFP structure and timing）

  • CFP 的頻率（p.7）：PC 依 CFPRate（contention-free repetition rate）產生 CFP，CFPRate 以「幾個 DTIM 間隔」來定義。
    • 講義的圖：每 3 個 Beacon 有一個 DTIM，CFP repetition interval 橫跨 2 個 DTIM 間隔；每個 CFP 都從一個 DTIM Beacon 開始。
    • CFP 的長度可變（Variable Length），結束時 PCF 送 CF-End「Reset NAV」。
    • CFP 期間的每個 Beacon 都帶 CFP_Dur_remaining（CFP 還剩多久），站台據此設 NAV。
    • 若 CFP 該開始時媒介正忙，PCF 會延後（PCF Defers for Busy Medium），這個 CFP 就被縮短（Foreshortened CFP）。
  • Infrastructure 的 Beacon 產生（p.8）
    • Infrastructure 網路由 AP 送 Beacon，排在固定的 Beacon Interval。
    • Beacon 的傳送可能被 CSMA 延後（媒介忙）。
    • 但後續的 Beacon 仍照原本預定的 Beacon Interval：下一個 Beacon 在 Target Beacon Transmission Time（TBTT）送出，不是以上一次實際送出的時間起算。
    • Beacon 裡的 Timestamp 是真正送出那一刻的計時器值（"Actual time" stamp），所以即使 Beacon 晚送，收方對時仍然準確。
  • CFP 的長度（p.9）
    • 由 PC 控制，最長不超過 PC 設定的 CFPMaxDuration（放在 CF Parameter Set，由 Beacon 與 Probe Response 廣播）。
    • 因為 Beacon 可能因媒介忙而延後，CFP 會被縮短延後的那段時間。
    • Beacon 裡的 CFPDurRemaining 必須讓 CFP 的結束時間不晚於 TBTT + CFPMaxDuration。
    • 講義的圖：TBTT 時剛好有 DCF 流量在進行，最壞情況要等一整筆 RTS + CTS + MPDU + ACK（Max）結束，Beacon 才送得出去；後面的 CFP 只剩 CF MaxDuration 減掉這段。

6. PCF 存取與傳送程序（p.10–12）（PCF Access／Transfer Procedure）

  • 存取程序（1/2）（p.10）
    • PCF 協定由每個 BSS 裡一個特別的站台控制，稱為 Point Coordinator（PC），以輪詢（polling）為基礎。
    • PC 在 CF 期間開頭取得媒介控制權，之後每次傳送之間都只等較短的時間，所以整個 CF 期間都握有控制權。
    • CF 開頭，PCF 感測媒介；若空閒，就等 PIFS，然後送出：
      • 一個 Subtype 設了 CF-Poll 位元的 Data 訊框，給輪詢清單（polling list）上的下一個站台；或
      • 一個 CF-End 訊框，如果這次想要一個空的（null）CF 期間。
  • 存取程序（2/2）（p.11）
    • PCF 用的是 PCF 優先等級：較短的 PIFS 讓突發流量的訊框間隔，比競爭期站台需要的 DIFS 還短。
    • 除了 PC 自己，每個站台在每個 SF 開頭都把 NAV 預設成最大的 CF 期間長度（CFPMaxDuration）。
    • CF 期間結束時，PC 送 CF-End 或 CF-End + ACK，重設 BSS 內所有站台的 NAV。
  • 傳送程序（p.12）：PC 是傳送端或接收端時
    • 站台收到 CF-Poll 時，若佇列裡有訊框，要隔 SIFS 立即送出。
    • 這樣就形成一段無競爭流量的突發（CF-Burst）。
    • 需要 MAC 層確認的服務，ACK 最好透過回應的 CF-Up 訊框 Subtype 裡的 CF-Ack 位元來做（捎帶）。
PCF 一次超級訊框：點名、捎帶確認、CF-End 動畫
依講義第 4、12 頁重繪（時間比例為示意）。Dx = 下行（AP → STA）、Ux = 上行（STA → AP）。黃色是 DCF 站台的 NAV：CFP 開頭設成 CF_Max_Duration，CF-End 一到就重設。
  • 看懂 p.12 的訊框名稱：
    • CF-D1：D1 + Poll　送資料給 STA1，順便點名 STA1。
    • CF-U1：U1 + Ack　STA1 回自己的資料，順便確認收到 D1。
    • CF-D2：D2 + Ack + Poll　確認 U1、送資料給 STA2、點名 STA2。
    • CF-D3：Ack + Poll　確認 U2、點名 STA3（沒有下行資料）。STA3 沒有回應，PC 等 PIFS 就接著送下一個。
    • CF-D4：D4 + Poll、CF-U4：U4 + Ack。
    • CF-End + Ack　確認 U4 並結束 CFP，所有站台重設 NAV，進入 CP。
  • 補充為什麼沒回應時等 PIFS 而不是 SIFS：PC 要先確定被點名的站台真的沒有在 SIFS 後開始送；PIFS 仍比 DIFS 短，所以 DCF 站台還是插不進來。

8. 同步：TSF（p.15–16）（Timing Synchronization Function）

  • TSF 的三個用途（p.15）
    1. 省電管理：Beacon 在大家都知道的時間間隔送出，BSS 內所有站台的計時器同步，站台才知道什麼時候該醒來。
    2. Point Coordination 的時序：用 TSF Timer 預測無競爭突發（CF burst）什麼時候開始。
    3. FH PHY 的跳頻時序：用 TSF Timer 計算駐留時間（Dwell Interval）；所有站台同步，才能在同一時間一起跳頻。
  • 同步的做法（p.16）
    • 每個站台都維護一個本地計時器（local timer）。
    • TSF 讓所有站台的計時器保持同步：Infrastructure 由 AP 控制時間；Independent BSS（IBSS）則是分散式的。
    • 時間由週期性的 Beacon 傳遞：Beacon 帶有整個 BSS 的 Timestamp，站台用它校正本地時鐘。
    • 不必聽到每一個 Beacon 才能保持同步（時鐘短時間內不會偏太多）。
    • Beacon 也帶其他管理資訊，也用於省電管理與漫遊。
  • 補充TSF Timer 是 64 bits、單位 µs。Infrastructure 中站台直接採用 AP 的 Timestamp；IBSS 中站台只在收到的 Timestamp 比自己快時才採用，所以全網最後會跟著最快的時鐘走。

10. 省電管理（p.18–22）（Power Management）

  • 為什麼需要（p.18）
    • 行動裝置靠電池供電，省電對移動性很重要。
    • 現有的 LAN 協定假設站台隨時準備好接收；長時間來看，閒置時的接收狀態佔網卡耗電的大部分。
    • 問題：怎麼在閒置時關掉收發器，又維持連線（active session）？
    • 802.11 省電協定：讓收發器盡量關閉；對既有協定透明（上層不必知道）；有彈性，可以在吞吐量與電池壽命之間取捨。
  • 做法（p.19）
    • 允許閒置的站台去睡覺；站台的省電模式記在 AP。
    • AP 替睡著的站台緩衝封包，並宣告哪些站台有緩衝的訊框：每個 Beacon 都帶 Traffic Indication Map（TIM）。
    • 省電站台定期醒來聽 Beacon。
    • TSF 確保 AP 與省電站台同步：站台會準時醒來聽 Beacon；睡覺時 TSF Timer 繼續跑；同步讓極低功耗的運作成為可能。
    • IBSS 也有省電管理：概念類似，但是分散式的做法（第 11 節）。
  • Infrastructure 省電（p.20–22）
    • 廣播訊框也在 AP 緩衝：所有廣播／群播都先緩衝，只在 DTIM 之後送出（DTIM：Delivery Traffic Indication Message）。
    • DTIM 間隔是 TIM 間隔的整數倍（講義圖：每 3 個 TIM 一個 DTIM）。
    • 站台在預期的 (D)TIM 之前醒來。
    • 如果 TIM 顯示有自己的緩衝訊框：站台送 PS-Poll（帶 AID），並保持清醒收資料；否則再回去睡。
  • 補充站台用 Frame Control 的 Pwr Mgt 位元告訴 AP「我要進入省電模式」；AID（Association ID）是 Association 時 AP 分配的編號，TIM 的 Partial Virtual Bitmap 每個 bit 對應一個 AID。PS-Poll 的 Duration/ID 欄位放的就是 AID。
Infrastructure 省電：TIM、DTIM、PS-Poll 動畫
依講義第 20–22 頁重繪。上排是 AP，下排是省電站台（高 = 醒著、低 = 睡覺）。每 3 個 TIM 一個 DTIM，DTIM 後送出緩衝的廣播；第 5 個 TIM 顯示 AP 有站台的資料，站台送 PS-Poll 取件。
TIM 的 Partial Virtual Bitmap 互動 補充
點格子切換「AP 有沒有這個 AID 的緩衝資料」。AID n 對應第 ⌊n ÷ 8⌋ 個 octet 的第 (n mod 8) 個 bit；AID 0 保留給廣播／群播（DTIM 時用）。

11. IBSS 省電管理：ATIM（p.23–24）（IBSS Power Management）

  • ATIM：Ad Hoc（Announced）Traffic Indication Message，IBSS 沒有 AP 幫忙緩衝，改由傳送端自己在 ATIM window 裡通知接收端。
  • 省電中的站台要在每個 TBTT 之前進入清醒狀態（Awake）。
  • 收到 ATIM 的站台，要保持清醒直到下一個 ATIM window 結束。
  • 送出 Beacon 或 ATIM 管理訊框的站台，也要保持清醒直到下一個 ATIM window 結束。
  • 用 RTS/CTS 偵測某個站台是不是在省電模式（對方沒回 CTS，可能就是睡著了）。
  • ATIM window 內只能送：RTS、CTS、ACK 控制訊框，以及 Beacon、ATIM 管理訊框；其他類型都不行。
  • 真正的資料傳送在 ATIM window 之後開始，用 DCF（退避）。
IBSS：ATIM window 通知，之後傳資料 動畫
依講義第 24 頁重繪。第一個 Beacon Interval 沒有人送 ATIM，大家在 ATIM window 結束後都回去睡；第二個 Beacon Interval A 有資料給 B：A 送 ATIM、B 回 ACK，window 結束後 A 送資料、B 回 ACK。C 沒收到 ATIM，照樣睡覺。

⚠️ 講義勘誤（p.23）

原文：「Transmission is begin following the ATIM window」
正確：「Transmission begins following the ATIM window」

理由：文法錯誤。

待確認 待確認

p.23 把 ATIM 寫成「Ad Hoc（Announced）Traffic Indication Message」，p.5 的 Subtype 表則寫「Announcement traffic indication message（ATIM）」。補充IEEE 802.11 標準的正式名稱是 Announcement Traffic Indication Message；「Ad Hoc」應是強調它只用在 IBSS。考試寫 Announcement 較保險。

12. 掃描（p.26–29）（Scanning）

  • 為什麼要掃描（p.26）：找到並加入網路、漫遊時找新的 AP、建立 Independent BSS（ad hoc）網路。
  • 802.11 MAC 對所有 PHY 用同一套掃描機制：單頻道或多頻道都可以，被動或主動掃描。
  • Beacon 或 Probe Response 裡都帶有加入新網路所需的資訊。
被動掃描（Passive Scanning）主動掃描（Active Scanning）

  • 頻道掃描規則（p.27）：站台要用被動或主動其中一種模式。
    • 掃描後找不到想要 SSID 的 BSS、或根本找不到任何 BSS，站台可以自己建立 IBSS。
    • 站台也可以不掃描就直接建立自己的 BSS。
  • 主動掃描的步驟（p.28 Active Scanning Example，加入 AP 的流程）：
    1. 站台送 Probe Request。
    2. 各 AP 回 Probe Response。
    3. 站台選出最好的 AP。
    4. 站台送 Association Request 給選定的 AP。
    5. AP 回 Association Response。
    這是第一次連上 AP 的流程；Reassociation 的流程類似。
  • 主動掃描的時序（p.29），對每個要掃描的頻道：
    1. 送一個 Probe Request，目的位址為廣播、帶 SSID 與廣播 BSSID。
    2. 啟動 ProbeTimer。
    3. 如果在 Min_Probe_Response_Time 之前都沒收到回應：清除 NAV，掃描下一個頻道。
    4. 否則，等 ProbeTimer 到 Max_Probe_Response_Time，處理所有收到的 Probe Response，再掃描下一個頻道。
    講義的圖：Responder 2 先回 P RESPONSE，掃描站台隔 SIFS 回 ACK；Responder 1 等 DIFS 並退避後才回，也收到 ACK。Probe Response 是單播的管理訊框，要照 DCF 競爭，也要回 ACK。

13. Infrastructure 網路與漫遊（p.30–32）（Roaming）

  • Infrastructure 網路（p.30）：每個站台都和一台特定的 AP Association。講義例子：Station 1、2、3 → AP A；Station 4、5 → AP B；Station 6、7 → AP C。
  • 漫遊（p.31）：行動站台可能移到目前 AP 的涵蓋範圍之外，但在另一台 AP 的範圍之內；Reassociation 讓站台繼續運作。
  • 漫遊的做法（p.32）
    1. 站台判斷和目前 AP 的連線變差。
    2. 站台用掃描找另一台 AP，或用之前掃描得到的資訊。
    3. 站台送 Reassociation Request 給新 AP。
    4. 如果 Reassociation Response 成功 → 站台已漫遊到新 AP；否則再掃描找別台 AP。
    5. AP 接受 Reassociation Request 後：AP 向分送系統（Distribution System, DS）表明這次 Reassociation，DS 的資訊被更新，通常也透過 DS 通知舊 AP。
走過三台 AP：什麼時候 Reassociation？ 互動
依講義第 30–32 頁重繪。補充訊號強度用簡化的距離模型示意；站台只在目前 AP 的訊號低於門檻時才換，避免在兩台 AP 中間來回跳（遲滯）。

14. 公式與計算

講義本身幾乎沒有數字，下面的數值例子多半是 補充，參數取標準常見值。單位提醒：1 TU（Time Unit）= 1024 µs；Beacon Interval 常見 100 TU = 102.4 ms。

CFP 多久出現一次

CFP repetition interval = CFP Period × DTIM Period × Beacon Interval（講義：CFPRate 以 DTIM 間隔的個數定義）
  1. 講義 p.7 的圖：每 3 個 Beacon 一個 DTIM（DTIM Period = 3），每 2 個 DTIM 一次 CFP（CFP Period = 2）→ 每 3 × 2 = 6 個 Beacon Interval 一次 CFP。
  2. Beacon Interval = 100 TU = 102.4 ms → CFP repetition interval = 6 × 102.4 = 614.4 ms。

CFP 最晚何時結束（foreshortened CFP）

CFP 結束時間 ≤ TBTT + CFPMaxDuration　→　實際 CFP 長度 = CFPMaxDuration − Beacon 延遲
  1. 最壞的延遲是 TBTT 時剛好有一整筆 DCF 交換在進行（講義 p.9：Max RTS + CTS + MPDU + ACK）。
  2. 用 2-4 的 802.11a 54 Mbps、1500 bytes 數字：RTS 24 + SIFS 16 + CTS 24 + SIFS 16 + DATA 248 + SIFS 16 + ACK 24 = 368 µs，再加 PIFS 25 µs 才送 Beacon → 延遲約 393 µs。
  3. 若 CFPMaxDuration = 50 TU = 51,200 µs，這個 CFP 只剩 51,200 − 393 = 50,807 µs；Beacon 裡的 CFPDurRemaining 就填這個值，確保 CFP 仍在 TBTT + 51,200 µs 結束。

計算陷阱：CFP 被縮短的是「結束時間不變、開始時間延後」，不是整個 CFP 往後平移。

PCF 的優先權：PIFS vs. DIFS

PIFS = SIFS + Tslot ＜ DIFS = SIFS + 2 Tslot（2-4 第 6 節）
  1. OFDM（11a）：PIFS = 16 + 9 = 25 µs，DIFS = 16 + 18 = 34 µs；PC 比任何 DCF 站台早 9 µs 搶到媒介。
  2. CFP 內訊框之間只隔 SIFS（16 µs）；被點名的站台沒回應時 PC 等 PIFS（25 µs）：兩者都 ＜ DIFS，DCF 站台整段 CFP 都插不進來（再加上 NAV 保護）。

IBSS Beacon 的隨機延遲

延遲 = Random[0, 2 × CWmin] × Slot_time（講義 p.17）
  1. DSSS（CWmin 31、slot 20 µs）：最大 2 × 31 × 20 = 1240 µs，共 63 個可能值。
  2. OFDM（CWmin 15、slot 9 µs）：最大 2 × 15 × 9 = 270 µs，共 31 個可能值。
  3. 補充兩個站台抽到同一個值（Beacon 碰撞）的機率：DSSS 1 ÷ 63 ≈ 1.6%；OFDM 1 ÷ 31 ≈ 3.2%。範圍是一般退避 [0, CWmin] 的兩倍，就是為了讓這個機率更小。

Frame Control 第一個 octet

octet = Subtype × 16 + Type × 4 + Protocol Version（version 目前是 0）
  1. Beacon：Type 00、Subtype 1000 → 8 × 16 + 0 × 4 = 128 = 0x80。
  2. PS-Poll：Type 01、Subtype 1010 → 10 × 16 + 1 × 4 = 164 = 0xA4。
  3. CF-End：Type 01、Subtype 1110 → 14 × 16 + 4 = 228 = 0xE4；CF-End + CF-Ack → 0xF4。
  4. Data + CF-Poll：Type 10、Subtype 0010 → 2 × 16 + 2 × 4 = 40 = 0x28；Data + CF-Ack + CF-Poll → 0x38。
  5. ATIM：Type 00、Subtype 1001 → 0x90；Probe Request → 0x40；Reassociation Request → 0x20。

補充TIM 的 AID 位置

AID n → 第 ⌊n ÷ 8⌋ 個 octet 的第 (n mod 8) 個 bit
  1. AID 13：13 ÷ 8 = 1 餘 5 → octet 1 的 bit 5（0010 0000 = 0x20）。
  2. AID 3 和 AID 13 都有資料：octet 0 = 0000 1000 = 0x08，octet 1 = 0x20。

補充省電可以省多少

清醒比例 ≈ 每次醒來的時間 ÷（Beacon Interval × Listen Interval）
  1. 每次醒來聽 Beacon 約 2 ms，Beacon Interval 102.4 ms，每個 Beacon 都醒：2 ÷ 102.4 ≈ 2.0%。
  2. Listen Interval = 3（每 3 個 Beacon 醒一次）：2 ÷ 307.2 ≈ 0.65%，但資料最多要多等約 300 ms 才收得到 → 這就是講義說的「在吞吐量（延遲）與電池壽命之間取捨」。
  3. 要收廣播的站台，至少要在每個 DTIM 醒來（DTIM Period 3 → 同樣每 307.2 ms）。

補充掃描要花多久

  1. 主動掃描 2.4 GHz 的 11 個頻道，假設 Min_Probe_Response_Time 10 ms、Max 40 ms：全部沒 AP → 11 × 10 = 110 ms；每個頻道都有 AP → 11 × 40 = 440 ms。
  2. 被動掃描每個頻道至少要等一個 Beacon Interval：11 × 102.4 ≈ 1126 ms，約是主動掃描的 2.5～10 倍。

16. 複習問題

觀念題

1. PCF 怎麼保證 CFP 期間 DCF 站台插不進來？列出兩層保護。
① 時間：PC 只等 PIFS 就開始 CFP，CFP 內訊框間隔都是 SIFS（被點名者沒回時 PIFS），都比 DCF 站台要等的 DIFS 短。② NAV：每個站台在 SF 開頭把 NAV 設成 CFPMaxDuration（並依 Beacon 的 CFPDurRemaining 更新），虛擬載波感測一直認為媒介忙，直到 CF-End 重設 NAV。
2. 為什麼下一個 Beacon 排在 TBTT，而不是上一次 Beacon 實際送出的時間加一個 Beacon Interval？
如果從實際送出時間起算，每次因媒介忙造成的延遲會一路累積，Beacon 越來越晚，省電站台算好的醒來時間就會錯過 Beacon。排在固定的 TBTT，延遲只影響那一次；Beacon 裡的 Timestamp 記錄實際送出時間，所以對時仍然準確。
3. 廣播／群播為什麼只在 DTIM 之後送？
廣播的接收者是所有站台，其中有些在睡覺。AP 必須等大家都醒著的時刻才送；DTIM 就是約定好「所有省電站台都要醒來」的那個 Beacon，所以廣播／群播先緩衝，DTIM 之後再送。
4. IBSS 沒有 AP，省電站台怎麼知道有人要傳資料給它？
所有站台在每個 TBTT 前醒來，Beacon 後有一段 ATIM window。想傳資料的站台在 window 內送 ATIM 給接收端，接收端回 ACK，雙方保持清醒到下一個 ATIM window 結束；window 過後才用 DCF 傳資料。沒收到 ATIM 的站台在 window 結束後就回去睡。
5. 被動掃描與主動掃描各適合什麼情況？
被動掃描不發射、省電，適合不急著連線或不允許主動發射的頻道（例如需要 DFS 的 5 GHz 頻道）；主動掃描速度快，適合第一次連線或漫遊時要盡快找到新 AP。

計算題

6. Beacon Interval 100 TU、DTIM Period 2、CFP Period 3，CFP 多久出現一次（ms）？
3 × 2 × 100 = 600 TU = 600 × 1.024 = 614.4 ms。
7. CFPMaxDuration = 30 TU，TBTT 時媒介被一筆交換佔用 1.2 ms，PC 再等 PIFS 25 µs 送 Beacon。這個 CFP 實際最長多久？最晚何時結束？
30 TU = 30,720 µs；延遲 1,200 + 25 = 1,225 µs；實際最長 30,720 − 1,225 = 29,495 µs ≈ 29.5 ms；最晚在 TBTT + 30,720 µs 結束。
8. 寫出 CF-End + CF-Ack 與 Data + CF-Ack 的 Frame Control 第一個 octet。
CF-End + CF-Ack：Type 01、Subtype 1111 → 15 × 16 + 1 × 4 = 244 = 0xF4。Data + CF-Ack：Type 10、Subtype 0001 → 16 + 8 = 24 = 0x18。

情境應用題

9. 手機連上 AP 後幾乎不傳資料，但希望電池撐久，又不能漏接推播。該怎麼設定省電參數？
開啟省電模式，加大 Listen Interval（例如每 3～10 個 Beacon 醒一次），只醒來看 TIM；有自己的資料才送 PS-Poll。代價是推播延遲變長（最多多等 Listen Interval × Beacon Interval）。若需要收廣播（例如 ARP），還要在每個 DTIM 醒來，所以 AP 端的 DTIM Period 也會影響耗電。
10. 使用者從辦公室 A 區走到 B 區，視訊通話會短暫卡住。從講義的漫遊流程看，卡住發生在哪幾步？怎麼縮短？
卡住發生在「判斷連線變差 → 掃描找新 AP → Reassociation Request／Response → 新 AP 通知 DS、更新轉送資訊」。縮短的方法：利用之前的掃描結果（講義 p.32 的 use information from previous scans），省掉掃描時間；用主動掃描代替被動掃描；適當調整「連線變差」的門檻，提早在背景找好新 AP。

17. 一頁速記

  1. PCF：選用、PC 在 AP、建在 DCF 上；提供 Time Bounded Services（低延遲變化）。
  2. Superframe = CFP（PCF 點名）＋ CP（DCF 競爭）；CFP 長度每個 SF 可變。
  3. CFP 開頭：媒介空閒 PIFS → Beacon；之後 SIFS 連發；點名者沒回 → PIFS 後繼續；CF-End（＋Ack）重設 NAV。
  4. 捎帶：Data + CF-Ack + CF-Poll 一個訊框同時送資料、確認、點名；Subtype b4 = Ack、b5 = Poll、b6 = no data。
  5. CFP Rate 以 DTIM 間隔個數定義；Beacon 延後 → CFP 縮短，最晚 TBTT + CFPMaxDuration 結束；Beacon 帶 CFPDurRemaining。
  6. MAC 管理層 = 同步（TSF、Beacon）＋ 省電（睡眠、緩衝、TIM）＋ Association／Reassociation（掃描、漫遊）＋ MIB。
  7. TSF 三用途：省電、PCF 時序、FH 跳頻；Infrastructure 由 AP 控制，IBSS 分散式；Beacon 照 TBTT 排、Timestamp 記實際送出時間。
  8. IBSS Beacon：每個 TBTT 抽 Random[0, 2 × CWmin] × slot，先數完的送，聽到別人的就放棄。
  9. 省電：AP 緩衝 → Beacon 的 TIM 宣告 → 站台醒來送 PS-Poll（帶 AID）取件；廣播只在 DTIM 後送；DTIM 間隔是 TIM 間隔的整數倍。
  10. IBSS 省電：TBTT 前醒來 → ATIM window 內送 ATIM／ACK → window 後用 DCF 傳；ATIM window 只能送 RTS、CTS、ACK、Beacon、ATIM。
  11. 掃描：被動聽 Beacon（ChannelTime）、主動送 Probe（Min／Max_Probe_Response_Time）；Probe Request → Response → 選 AP → Association Request → Response。
  12. 漫遊：連線變差 → 掃描（或用舊結果）→ Reassociation Request → 成功就換過去 → 新 AP 通知 DS、DS 通知舊 AP。

19. 考前自我檢查

  • 畫出 PCF 蓋在 DCF 上的架構，說出 PC 在哪裡、PCF 支援什麼服務
    PHY → DCF（CSMA/CA）→ PCF（Optional）；PC 位在 AP；支援 Time Bounded Services（較低的傳送延遲變化），也可傳非同步資料。
  • 說明 Superframe 的組成與 CFP 長度怎麼決定
    SF = CFP + CP；CFP 長度可變、最長 CFPMaxDuration；CFP 每隔 CFP Period 個 DTIM 間隔出現一次。
  • 畫出 p.12 的 PCF 傳送時序並解釋 D3 沒回應時怎麼辦
    PIFS → Beacon → SIFS → D1+Poll → SIFS → U1+Ack → SIFS → D2+Ack+Poll → U2+Ack → Ack+Poll（D3）→ 沒回應，PIFS → D4+Poll → U4+Ack → CF-End+Ack → Reset NAV → CP。
  • 寫出 Beacon、PS-Poll、CF-End、Data + CF-Poll 的 Type／Subtype 與第一個 octet
    Beacon 00/1000 = 0x80；PS-Poll 01/1010 = 0xA4；CF-End 01/1110 = 0xE4；Data + CF-Poll 10/0010 = 0x28。
  • 說明 foreshortened CFP 與 CFPDurRemaining
    Beacon 因媒介忙延後，CFP 開始得晚，但必須在 TBTT + CFPMaxDuration 前結束，所以變短；Beacon 的 CFPDurRemaining 填剩下的時間。
  • 說出 MAC 管理層的四個功能
    同步、省電管理、Association 與 Reassociation、MIB。
  • 說出 TSF 的三個用途與 Infrastructure／IBSS 的差別
    省電、PCF 時序、FH 跳頻時序；Infrastructure 由 AP 控制時間，IBSS 分散式。
  • 解釋 TBTT 與 Timestamp，以及 Beacon 被延後時下一個怎麼排
    TBTT 是預定時刻，Timestamp 是實際送出時間；下一個 Beacon 仍在下一個 TBTT，不從上一次實際送出時間起算。
  • 寫出 IBSS 在每個 TBTT 的 Beacon 產生步驟
    暫停其他退避 → 抽 [0, 2 × CWmin × Slot] 的隨機延遲 → 退避 → 聽到別人的 Beacon 就放棄，否則送出。
  • 畫出 Infrastructure 省電的 TIM／DTIM／PS-Poll 時序
    站台在 (D)TIM 前醒來；TIM 顯示有資料 → 送 PS-Poll（帶 AID）並保持清醒收資料；沒有 → 回去睡；廣播在 DTIM 後送。
  • 說明 IBSS 的 ATIM window 規則
    TBTT 前醒來；收到或送出 ATIM（或送 Beacon）就保持清醒到下一個 ATIM window 結束；window 內只能送 RTS、CTS、ACK、Beacon、ATIM；資料在 window 後用 DCF 送。
  • 比較被動與主動掃描，說出主動掃描的 Min／Max_Probe_Response_Time 規則
    被動聽 Beacon、主動送 Probe Request；Min 之前沒回應就換頻道，否則等到 Max 處理所有回應再換頻道。
  • 寫出加入 AP 與漫遊的步驟
    加入：Probe Request → Probe Response → 選最好的 AP → Association Request → Association Response。漫遊：連線變差 → 掃描或用舊結果 → Reassociation Request → 成功則換過去 → 新 AP 通知 DS → DS 通知舊 AP。
