0. 怎麼用這張小抄

考場流程：看題目 → 在 ① 用題目的英文字眼找到機制與卡片編號 → 用 ④ 的骨架決定答案的段落結構 → 到 K 卡 取「目的／運作／優缺點／比較」的內容 → 題目問「為什麼」時，從 ③ 找出是哪一個無線特性造成的 → 計算題到 ⑥ 找公式與常數。
  • 正面（找入口、推答案）：① 題目字眼索引、② OSI 七層、③ 無線特性推導表、④ 答題骨架、⑤ 跨章比較矩陣，以及 K1–K7 機制卡。
  • 背面（內容）：K8–K27 機制卡與 ⑥ 公式計算區。
  • 卡片上的符號：目目的（這個機制要解決什麼問題）、運運作（誰、何時、送什麼、用哪個欄位）、＋優點、－缺點、比要拿來比較的機制。紫色粗體 為何 是「為什麼這樣設計」的答案。補充 表示講義沒有、依標準或推理補上的內容，答題時可以寫，但要知道它不是講義原文。
  • 老師的出題風格：英文題目、觀念與跨章比較、反事實（「如果 X 改用 Y 會怎樣」）、優缺點、解釋名詞、限制條件（「不用 RTS/CTS 怎麼解」）。很少考規格細節，所以小抄重點放在「為什麼」與「比較」。

② OSI 七層：802 只做 L1、L2

考場上怎麼用：題目問「在哪一層解決」「為什麼 802.11 對上層透明」「封裝」時用。考試重點在 MAC 與 PHY，上面五層只要記得各做什麼。
  • L7 應用層：使用者的程式。L6 表達層：資料格式的轉換、壓縮、加密。L5 會議層：對話的建立與同步。L4 傳輸層：端對端的傳輸品質，例如 TCP。L3 網路層：繞送，例如 IP；Mobile IP 在這一層處理跨網段的移動。
  • L2 鏈結層：節點到節點傳送無錯誤的訊框。802 把它分成兩個子層：
    • LLC（邏輯鏈結控制，802.2）：所有 802 網路共用的上半部，所以上層看到的介面都一樣。
    • MAC（媒介存取控制）：決定誰何時能用共享媒介。802.11 的 MAC 還負責 ACK、重傳、分段、加密、省電、漫遊——有線 MAC 不需要做的事，無線都要在這裡做。
  • L1 實體層：傳送位元流，不負責重傳。802.11 分成：
    • PLCP（實體層匯聚協定）：加上前導碼與標頭，並提供 CCA（通道是否閒置的判斷）給 MAC。
    • PMD（實體媒介相依子層）：實際的調變與天線。
  • 封裝：MSDU（LLC 交給 MAC 的資料）→ MAC 加上標頭與 FCS 成為 MPDU；MPDU 交給 PLCP 時叫 PSDU（同一串位元，從 PHY 的角度稱呼）→ PLCP 加上前導碼與標頭成為 PPDU，由 PMD 送出。一般規則：上一層交下來的 SDU＋本層標頭＝本層的 PDU。
  • 為何 802 只做 L1、L2：各種 LAN 的差別只在媒介與存取方式，上層都透過共用的 LLC，所以無線網路對 IP 是透明的；也因此「站台會移動」這件事必須在 MAC 內部解決，不能丟給上層。
  • LAN 的需求（講義用來評價 MAC 的標準）：1–1000 Mbps、1–5 km、數百台站台、盡量不依賴集中控制、高負載下仍穩定、公平、可靠、低成本。答「評價某個 MAC」的題目時，可以拿這幾項逐一檢查。

③ 無線的特性 → 後果 → 機制

考場上怎麼用：這是「為什麼」的來源。題目問「為什麼 802.11 需要 X」「為什麼 Ethernet 不用 X」「X 改用 Y 會怎樣」，就從這張表找出是哪個特性，照「特性 → 沒有這個機制會怎樣 → 機制怎麼解 → 代價」寫成一段。
  1. 送的時候聽不到別人 → 不能做碰撞偵測（CD）。無線電發射時自己的訊號遠比收到的強，無法邊送邊聽；而且碰撞發生在接收端，傳送端不一定聽得到。所以 802.11 改成碰撞避免（CA）：先等 DIFS、再隨機退避，送出後靠接收端回的正向 ACK 才知道成功，失敗就把競爭視窗 CW 加倍。（K2、K4、K5）
  2. 不能假設所有站台都聽得到彼此 → 隱藏節點。兩個彼此聽不到的站台可能同時傳給同一個接收端。對策：NAV 與 RTS/CTS 讓接收端周圍的站台也知道媒介被佔用；或讓所有流量都經過大家都聽得到的 AP；或由 AP 輪詢。（K6、K9）
  3. 干擾、雜訊、通道隨時間與位置改變 → 錯誤率高。對策：ACK＋重傳；分段讓錯誤時只重送一段；Retry 位元配合序號刪除重複訊框；收到錯誤訊框時用 EIFS 保護別人的 ACK。（K5、K7、K3）
  4. 站台會移動 → 位址不等於位置。有線網路的位址就代表接在哪個埠，無線不是。對策：Association 建立「站台在哪個 AP」的對應、DS 依對應遞送、Reassociation 在換 AP 時更新、掃描找新的 AP。（K13–K15）
  5. 靠電池 → 不能一直開著接收。對策：TIM／PS-Poll 讓 AP 替睡眠的站台緩衝；IBSS 用 ATIM；802.11e 的 APSD 降低延遲；這些都需要 TSF 讓大家對時，才能在同一時間醒來。（K10–K12、K26）
  6. 開放媒介、沒有實體邊界 → 誰都能接入、能竊聽。有線網路「接上線」就代表有權限、線路本身是封閉的。對策：用認證取代「接上線」、用 WEP 加密取代「封閉線路」、用站台狀態與訊框類別限制未認證者能送的訊框。（K14、K18）
  7. 有多種 PHY 與速率 → 有些站台聽不懂別人的資料。對策：PLCP 的前導碼與標頭用最低速率送，大家都聽得懂；LENGTH 欄位告訴別人要傳幾微秒；NAV；802.11g 有 11b 站台時先送 CTS 保護。（K19）
  8. 頻寬有限，每個訊框又有固定負擔 → 效率低。對策：TXOP（一次競爭送多筆）、Block Ack（多筆共用一個確認）、捎帶確認、DLS（不經 AP 轉送）。（K23–K25）
  9. 即時多媒體 → 需要有上限的延遲與抖動。對策：802.11e 的 EDCA（優先權）與 HCCA（參數化保證）。（K21、K22）
  10. 共用免執照的 ISM 頻段 → 干擾多。對策：展頻（DSSS 的 Barker 序列帶來約 10.4 dB 的處理增益）與選擇不重疊的頻道。（K20）
  11. 對照組：有線網路封閉、可靠、能做 CD。所以 Ethernet 不需要 ACK、認證、省電；但因為要做 CD，需要最小訊框 64 bytes（K1）。這一列是反事實題與「Ethernet 為什麼不用」題的答案來源。

④ 答題骨架

考場上怎麼用：先判斷題型，用對應的骨架決定段落，再從 K 卡填內容。骨架能確保不漏掉得分點（尤其是「為什麼」與「代價」）。
  • 比較／差異：一句話定位兩者 → 逐面向對照（運作方式、誰控制、碰撞、確認、效率、延遲／QoS、公平、省電、安全、適用組態）→ 各自適合什麼情境。盡量畫表，閱卷清楚。
    例：考古題 Q1（802.3 vs 802.11）、Q7（主動 vs 被動掃描）。
  • 優缺點：優點從效率、延遲、公平、簡單、相容找；缺點從負擔、延遲、複雜、需要協調者、隱藏節點、組態限制、沒有保證找 → 最後寫「誰改進了它」（後繼機制）。
    例：考古題 Q6（PCF）→ 結尾寫 HCCA 怎麼改進。
  • 為什麼這樣設計：在 ③ 找出特性 → 沒有這個機制會發生什麼 → 機制怎麼解決 → 付出什麼代價。
  • 反事實（X 改用 Y）：Y 成立的前提在 X 的環境裡成立嗎 → 失去了什麼 → 結果分「正確性」與「效率」兩面。
    例：無線改用 CD＝做不到（聽不到、碰撞在接收端）；有線改用 CA＝能用，但多了等待與 ACK、卻沒有好處。
  • 「不用某機制」：從四類工具找替代：架構（經過 AP、輪詢）、時間（IFS、EIFS、NAV、退避）、訊框（分段、短訊框、Duration）、PHY（發射功率、偵測門檻、速率）。
    例：考古題 Q8「不用 RTS/CTS 解決隱藏節點」。
  • 解釋題：目的（解決什麼）→ 運作（誰送、何時、用什麼欄位）→ 例子或相關機制。不要只翻譯名詞。
    例：考古題 Q3（QAM、More Data、Integration、Duration/ID）。
  • 定義題：一句定義 → 發生條件（最好畫站台位置圖）→ 後果 → 對策。
    例：考古題 Q8 的隱藏／暴露節點。
  • 計算題：先畫時間軸 → 列出每一段時間 → 加總 → 最後用一句話解釋這個數字代表什麼（例如「固定負擔不隨速率變小，所以效率下降」）。

⑤ 跨章比較矩陣

考場上怎麼用：比較題直接取欄位當比較面向；優缺點題用來找「相對於誰」的優缺點。五個存取方式：802.3 CSMA/CD、DCF、PCF、EDCA、HCCA。
  • 控制：802.3、DCF、EDCA 是分散式（每個站台自己競爭）；PCF（由 AP 中的 PC，點協調器，負責）與 HCCA（由 QAP 中的 HC，混合協調器，負責）是集中式。
  • 方式：802.3 先聽、送的時候也聽；DCF 競爭；PCF 輪詢；EDCA 是各個 AC（存取類別）之間競爭；HCCA 依 TSPEC 輪詢。
  • 碰撞：802.3 偵測到就停；DCF 與 EDCA 只能避免，靠 ACK 得知失敗；PCF 的 CFP（無競爭期）與 HCCA 的輪詢沒有碰撞。
  • 優先權：802.3 沒有；DCF 的 IFS 區分的是訊框種類（ACK 用 SIFS、資料用 DIFS），不是流量；PCF 用 PIFS 搶在 DCF 前；EDCA 用 AIFS、CW、TXOP 區分流量類別；HCCA 用排程。
  • 一次傳多少：802.3、DCF 一次一個訊框（DCF 的分段可以用 SIFS 連送）；PCF 每次輪詢一個訊框；EDCA 與 HCCA 給一段 TXOP，可以連送多筆。
  • 確認：802.3 沒有 MAC 層確認；DCF 每個訊框一個 ACK；PCF 可以把 CF-Ack 捎帶在資料訊框上；802.11e 可選 Normal ACK、No Ack、Block Ack。
  • QoS：802.3、DCF 沒有；PCF 不夠（理由見 K9）；EDCA 是統計式（機率上較快，不保證）；HCCA 是參數化保證。
  • 必備與否／組態：DCF 必備，ad hoc 與 infrastructure 都能用；PCF 選用、只能用在 infrastructure；EDCA 兩種組態都可；HCCA 只能用在 infrastructure。

演進表：一條功能從「舊 → 中 → 新」怎麼改進，適合回答「後來怎麼改善」。

  • 確認：802.3 沒有 → 802.11 每個訊框 ACK → 802.11e Block Ack、No Ack。
  • 優先權：沒有 → IFS（區分訊框種類）→ AIFS＋CW（區分流量類別）、TSPEC。
  • 一次傳：一個訊框 → 分段 burst（SIFS 連送）→ TXOP。
  • 省電：TIM／PS-Poll、DTIM、ATIM → U-APSD、S-APSD。
  • 隱藏節點：RTS/CTS＋NAV → 輪詢（PCF／HCCA）。
  • 存取控制：有線靠「接上線」→ Open System／Shared Key 認證、WEP → 802.1X、802.11i 補充。
  • 漫遊：Reassociation、預先認證 → IAPP（802.11f）、802.11r。
  • 直接傳：IBSS 可以直接傳，但 infrastructure 全部經過 AP → DLS。

誰發起：Association 與 Reassociation 只能由 STA 發起；Disassociation 與 Deauthentication 雙方都可以發起，而且是「通知」，對方不能拒絕（因為任何一方都可能需要離開，硬要維持沒有意義）。

機制卡 K1–K27

考場上怎麼用：每張卡依「目的 → 運作 → 優點 → 缺點 → 比較」排列，正好對應解釋題與優缺點題的段落。答題時先寫目的（一句），再寫運作（流程），最後寫優缺點或比較。

K1CSMA/CD＋BEB（802.3）

目的多個站台共用同一條線時，決定誰可以送。
運作先聽線路是否閒置 → 閒置就送，送的同時繼續聽 → 偵測到碰撞就送出 32 bits 的 jam 訊號讓大家都知道，然後停止 → 第 n 次碰撞後等待 r 個 slot，r 從 [0, 2k−1] 隨機選，k＝min(n, 10)。slot time 是 51.2 µs，等於訊號來回傳播加上偵測所需的時間。嘗試超過 16 次就放棄。
優點一撞就立刻停止，浪費的時間很少；整個訊框送完都沒偵測到碰撞，就幾乎可以確定成功，所以不需要 ACK。
缺點有「先進後出」的不公平（新來的站台退避範圍小，反而比較早送）；負載高時延遲變大；為了讓碰撞在送完前傳回來，需要最小訊框 64 bytes，網路長度也受限；只能用在有線網路。
比較和 K2 比：CD 是撞了之後才退避，退避只是單純等待、不會凍結；CA 是只要媒介忙過就退避，而且忙的時候計數器凍結。
名詞：CSMA/CD＝載波偵測多重存取／碰撞偵測。BEB（BEBA）＝截斷二元指數退避，碰撞越多次，隨機範圍加倍，最多到 210。jam＝讓所有站台都偵測到碰撞的干擾訊號。slot time＝退避的時間單位。

K2DCF（CSMA/CA）

目的在沒有中央控制者的情況下，讓所有站台公平地共享無線媒介。
運作實體載波偵測 CCA 與虛擬載波偵測 NAV 都顯示閒置 → 等 DIFS → 隨機退避 → 送出 → 接收端等 SIFS 後回 ACK；沒收到 ACK 就把 CW 加倍再試。DCF 是所有站台都必須實作的基本存取方式，ad hoc 與 infrastructure 都使用；PCF 與 HCF 都建立在 DCF 之上。
優點分散式、穩健（不依賴任何一台）、高負載下仍穩定、存取順序近似先到先服務。
缺點沒有 QoS；每個訊框的負擔大（前導碼、IFS、退避、ACK）；有隱藏節點問題；不保證頻寬公平——每個站台實際用到的頻寬可能不同，講義因此提出「要不要做負載分擔」的問題。
比較K1（有線的 CD）、K9（集中式的 PCF）、K21（加上優先權的 EDCA）。
名詞：DCF＝分散式協調功能。CCA＝PHY 判斷通道是否閒置。NAV＝記錄「媒介被預約到何時」的計時器。DIFS＝一般資料使用的訊框間隔。SIFS＝最短的訊框間隔。CW＝競爭視窗，退避值的隨機範圍。

K3IFS 訊框間隔（含 EIFS、AIFS）

目的用「媒介要閒置多久才能送」來給優先權，不需要額外的控制訊框。
運作由短到長：SIFS（ACK、CTS、回應輪詢、分段之間）＜ PIFS（PCF 的 PC 使用）＜ DIFS（DCF 的一般資料）＜ EIFS（收到錯誤訊框之後）。EIFS 不看 NAV，因為訊框有錯就讀不到裡面的 Duration；它的長度足夠讓別人用 1 Mbps 送完 ACK。802.11e 加入 AIFS[AC]＝AIFSN×slot＋SIFS，每個存取類別等不同的時間，而且一定大於 SIFS，以保護 ACK。802.11n 另有 RIFS。
優點SIFS 最短，所以一次訊框交換（Data–ACK、RTS–CTS）中間不會被別人插入；PIFS 比 DIFS 短，所以 PCF 能搶在 DCF 站台之前取得媒介。
缺點DCF 的 IFS 只區分訊框種類，所有站台的資料都用同一個 DIFS，所以沒辦法區分語音和一般資料。
名詞：IFS＝訊框間隔。PIFS＝PCF 用的訊框間隔。EIFS＝延伸訊框間隔。AIFS＝仲裁訊框間隔；AIFSN＝AIFS 的 slot 數。AC＝存取類別（語音、影像、盡力而為、背景）。RIFS＝縮減訊框間隔。

K4退避與 CW

運作退避時間＝Random[0, CW]×slot。媒介忙的時候計數器凍結，媒介閒置滿 DIFS 後從剩下的值繼續數。傳送失敗就把 CW 加倍（DSSS 從 31 到 1023；OFDM 從 15 起）。剛傳完、還有下一筆要送，也必須退避。例外：封包到達時媒介已經閒置超過 DIFS，可以直接送。
優點等得越久的站台，剩下的計數越小，越早送出，所以近似先到先服務；傳完也要退避，避免贏家一直霸佔媒介。
缺點媒介閒置時大家也在等，浪費時間；失敗過的站台 CW 已經變大，和新加入的站台競爭時仍然吃虧。
比較BEB：撞了才退避、只是單純等待；初始範圍小，因為有線的碰撞很便宜（立刻偵測、立刻停）。CA：初始範圍大，因為無線的碰撞很貴（整個訊框都浪費，還要等 ACK 逾時才知道）。

K5正向 ACK

目的無線偵測不到碰撞與錯誤，只能靠接收端回覆來確認。
運作接收端收對（CRC 正確）→ 等 SIFS 回 ACK；傳送端沒收到 ACK 就當作失敗 → 退避後重傳，直到重試上限（分 short／long retry count）。Data、Poll、Request、Response 訊框需要 ACK；廣播不回 ACK。ACK 遺失會讓傳送端重傳一個其實已經收到的訊框，接收端用 Retry 位元加上序號刪除重複的。
優點在 MAC 層就能快速復原，不必等上層（例如 TCP）逾時。
缺點每個訊框多一個 SIFS 加上一個 ACK 訊框（ACK 也有自己的 PLCP 前導碼與標頭）。
比較Ethernet 不用 ACK：它能偵測碰撞、線路可靠、可靠度交給上層的 LLC 或 TCP。802.11e 改成可選 No Ack、Block Ack。考古題 Q9 就是這張卡。
名詞：CRC＝循環冗餘檢查，放在 FCS 欄位，用來檢查訊框有沒有錯。Retry＝標頭中表示「這是重傳」的位元。

K6RTS/CTS＋NAV；隱藏／暴露節點

目的讓聽不到傳送端的站台，也知道媒介正被佔用。
運作傳送端送 RTS（帶 Duration）→ 接收端回 CTS（也帶 Duration），兩者把「還要佔用多久」分別散布到傳送端與接收端周圍 → 聽到的站台存進 NAV。NAV 或 CCA 任一個顯示忙碌就延後。只用在單播，而且訊框長度超過 RTS_Threshold 才用（是否使用可選，但每個站台都必須實作）。
優點碰撞只會損失一個短的 RTS，而不是整個資料訊框；NAV 是依公告的時間運作，所以在多種速率混用時仍然有效。
NAV 的來源（不只 RTS/CTS）：RTS/CTS；分段與 ACK 的 Duration；CFP 開始時設成 CFPMaxDuration（CF-End 重設）；802.11g 保護機制送的 CTS；HCCA 的 QoS CF-Poll（為 polled TXOP 設定）。另外 PLCP 的 LENGTH 欄位讓低速站台知道媒介會忙多久。收到錯誤訊框時讀不到 Duration，改用 EIFS。
缺點每個資料訊框多兩個控制訊框和兩個 SIFS，短訊框不划算；解決不了暴露節點。
隱藏節點：A、C 都在 B 的範圍內但彼此聽不到，同時送給 B，訊框在接收端 B 碰撞；傳送端聽不到對方，所以載波偵測防不了。暴露節點：A–B–C–D 排成一列，B 傳給 A 時，C 聽到 B 而延後，但 C 傳給 D 其實不會干擾 A；在 802.11 裡 C 還需要收 D 的 ACK，而 B 的訊號會干擾 C 收 ACK，所以這個機會也不能簡單利用。
不用 RTS/CTS 的解法（考古題 Q8）：infrastructure 模式（大家都聽得到 AP）；PCF／HCCA 輪詢（沒有競爭）；分段（每段的 Duration 扮演虛擬 RTS/CTS，碰撞也只毀掉一段）；EIFS（保護聽不懂的 ACK）；調整發射功率或偵測門檻讓站台彼此聽得到 補充。
名詞：RTS／CTS＝要求傳送／允許傳送。Duration＝標頭中公告佔用時間（微秒）的欄位。RTS_Threshold＝超過這個長度才使用 RTS/CTS。CFPMaxDuration＝CFP 的最長時間。CF-End＝結束 CFP 的訊框。TXOP＝一段可以連續傳送的時間。

K7分段與重組

目的錯誤率高時，短訊框比較容易成功；出錯也只需要重送一段 補充（講義寫的是「因應不同的實體層特性」）。
運作把 MSDU 切成不超過 Fragmentation_Threshold 的分段，各段等長（最後一段可以較短），使用同一個序號、分段號遞增，除了最後一段都設 More Fragments。各段之間用 SIFS 連送（fragment burst），每段各自 ACK。每段的 Duration 涵蓋「下一段＋它的 ACK」，等於虛擬的 RTS/CTS；最後一段的 Duration 是 0。接收端有計時器，逾時沒收齊就丟棄。
優點出錯時重傳的量小。
缺點多了標頭、PLCP 前導碼與 ACK。
比較802.3 有最小訊框（為了 CD）、不分段（線路可靠）。分段過程中若某段的 ACK 遺失：聽得到傳送端的站台照 NAV 繼續等，只聽得到目的端的站台沒收到 ACK，可以自由存取媒介。
名詞：MSDU＝上層交給 MAC 的資料單元。Fragmentation_Threshold＝分段門檻。More Fragments＝標頭中表示「後面還有分段」的位元。

K8廣播／群播

廣播與群播不用 RTS/CTS、不回 ACK，所以沒有 MAC 層的復原機制（例外：STA 把它送給 AP 時 To DS＝1，這一段是單播，有 ACK）。傳送者自己也會收到 AP 轉送回來的廣播，所以要過濾 SA 是自己的訊框。只要有站台在省電，AP 會把廣播／群播緩衝到 DTIM 之後再送。廣播會傳遍整個 ESS。
名詞：To DS＝標頭中表示「送往 DS」的位元。SA＝原始來源位址。DTIM＝傳送廣播／群播的 Beacon。ESS＝多個 BSS 經 DS 串起來的延伸服務集。

K9PCF

目的提供無競爭存取，支援有時間限制的服務（例如語音）。
運作PC 在 AP 裡。CFP 開始時 PC 等 PIFS 後送 Beacon → 所有站台把 NAV 設為 CFPMaxDuration → PC 依序送 CF-Poll 給被點名的站台（可以和資料、CF-Ack 合併成一個訊框）→ 被點名的站台等 SIFS 回應（沒資料就回 Null）→ PC 送 CF-End 重設 NAV → 進入 CP，大家用 DCF 競爭。CFP 每隔若干個 DTIM 出現一次；Beacon 若因媒介忙而延後，CFP 就被縮短，最晚在 TBTT＋CFPMaxDuration 結束。
優點CFP 中沒有碰撞、延遲變化小；和 DCF 共存在同一個超級訊框中；可以捎帶確認，減少控制訊框；所有站台都聽得到 AP，減少隱藏節點的影響。
缺點每次輪詢只能送一個訊框；PC 不知道各流量的 QoS 需求，無法保證頻寬、延遲、抖動；CFP 會被縮短，時間不可預測；輪到沒資料的站台浪費時間；只能用在 infrastructure；對 PC 隱藏的站台聽不到 Beacon、不會設 NAV，會在 CFP 中干擾；商用產品幾乎沒有實作。
比較K22 的 HCCA 逐點改進了這些缺點。考古題 Q6。
名詞：PCF＝點協調功能。PC＝點協調器。CFP／CP＝無競爭期／競爭期，兩者合起來是一個超級訊框。CF-Poll＝輪詢訊框。CF-Ack＝無競爭期中的確認，可以捎帶在其他訊框上。TBTT＝預定送 Beacon 的時間。

K10TSF 同步、Beacon、TBTT

目的讓整個 BSS 的時鐘一致。省電（大家同時醒）、PCF 時序、FH 跳頻（同時換頻道）、S-APSD（定時醒來）都依賴它。
運作infrastructure：AP 在每個 TBTT 送 Beacon，裡面的 timestamp 是送出當下的計時器值，站台用它校正自己的時鐘。TBTT 依固定排程，不是相對於上一個 Beacon，所以 Beacon 延後也不會讓之後的時程漂移；站台也不必每個 Beacon 都聽到。IBSS：每個 TBTT，每個站台等一段 [0, 2·CWmin·slot] 的隨機時間，先聽到別人的 Beacon 就取消自己的。
Beacon 內容：timestamp、Beacon 間隔、能力資訊、SSID、支援速率、參數組（包括 CF 參數組）、TIM。Probe Response 的內容和 Beacon 一樣，只是沒有 TIM。
名詞：TSF＝計時同步功能。Beacon＝AP 定期廣播的管理訊框。FH＝跳頻展頻。SSID＝網路名稱。TIM＝流量指示圖。

K11省電（infrastructure）

運作STA 把 Power Management 位元設為 1，告訴 AP 自己要睡 → AP 緩衝給它的訊框 → STA 在 Beacon 前醒來，看 TIM 裡（依 AID）有沒有自己 → 有就送 PS-Poll（帶 AID），並保持清醒接收；More Data＝1 表示還有，繼續要 → 沒有就再睡。廣播／群播等 DTIM 才送；DTIM 間隔是 TIM 間隔的倍數。考古題 Q2。
優點對上層透明；可以在吞吐量／延遲與電池之間取捨（睡越久越省電、延遲越長）。
缺點下行資料要等 Beacon 才能送：Beacon 間隔 100 ms 時，延遲是 100–300 ms，遠超過語音要求；每一筆緩衝資料都要一個 PS-Poll。
比較K26 的 APSD 解決這兩個缺點。
名詞：AID＝關聯時 AP 分配的識別碼。PS-Poll＝省電輪詢。More Data＝標頭中表示「還有緩衝資料」的位元。

K12IBSS（ad hoc）與 ATIM

IBSS 沒有 DS，所以只有站台服務（SS）、只用 Class 1 訊框、BSSID 用亂數產生（沒有 AP 的 MAC 位址可用）、Beacon 由大家分散產生。
省電：沒有 AP 可以緩衝，所以省電站台在 TBTT 前醒來 → 在 ATIM 視窗內，有資料要送的站台送 ATIM 給對方 → 對方回 ACK，並保持清醒到下一個 ATIM 視窗結束。視窗內只能送 RTS、CTS、ACK、Beacon、ATIM；視窗結束後用 DCF 傳資料。
名詞：IBSS＝獨立基本服務集（ad hoc 網路）。ATIM＝宣告流量指示訊息。BSSID＝BSS 的識別碼。

K13掃描

被動掃描（Passive）：在每個頻道只聽 Beacon，最多聽 ChannelTime；不發射，所以省電、不增加流量 補充，但要等 Beacon，比較慢。
主動掃描（Active）：在每個頻道送 Probe Request（指定 SSID 或廣播）→ MinProbeResponseTime 內沒有回應就換下一個頻道，有回應就等到 MaxProbeResponseTime 收齊；比較快，但耗電、佔用頻道 補充。
用途：加入網路、漫遊時找新 AP、建立 IBSS；找不到想要的網路時可以自己建一個 IBSS。掃描之後：選最好的 AP → 認證 → Association。考古題 Q7。
名詞：Probe Request／Response＝探測要求／回應。ChannelTime、Min／MaxProbeResponseTime＝每個頻道停留時間的參數。

K14認證、關聯、漫遊、狀態

目的認證取代有線網路的「接上線」，確立身分；關聯讓 DS 知道這個 STA 在哪個 AP 底下。
運作State 1（未認證）→ 認證 → State 2（已認證）→ 關聯 → State 3（已關聯）。Class 1 訊框任何狀態都能送：RTS、CTS、ACK、Beacon、Probe、Authentication、Deauthentication、ATIM；Class 2 要 State 2 以上：(Re)Association、Disassociation；Class 3 要 State 3：經過 DS 的資料、PS-Poll。收到未認證者送來的訊框 → 回 Deauthentication。
Class 1 為何不用認證：找網路（Beacon、Probe）和參與共用媒介的協定（RTS、CTS、ACK）是加入網路之前就必須做的，否則永遠加入不了，也會變成不設 NAV 的干擾者 補充。
認證在鏈結層，不是端對端；方法有 Open System 與 Shared Key（挑戰／回應）。一個 STA 同時只能和一個 AP 關聯，但可以先對多個 AP 認證（預先認證），漫遊時就只需要重新關聯，比較快。
漫遊：和目前 AP 的連線變差 → 掃描（或用之前的結果）→ 向新 AP 送 Reassociation Request → 新 AP 通知 DS，舊 AP 經由 DS 得知。跨 AP 的協調在 L2 有 IAPP（802.11f），跨網段在 L3 有 Mobile IP。
名詞：Authentication／Deauthentication＝認證／解除認證。Association／Reassociation／Disassociation＝關聯／重新關聯／解除關聯。Open System＝開放系統認證（實際上不驗證）。Shared Key＝共享金鑰認證。IAPP＝存取點間協定。

K15DS、Distribution、Integration、Portal

目的在「位址不等於位置」的情況下，仍然讓上層看到一個普通的 802 LAN。
運作DS 把多個 BSS 串成一個 ESS，對 LLC 來說整個 ESS 就像一個 BSS。Distribution 服務依關聯資訊找出目的地在哪個 AP（輸出點）；目的地若在有線 LAN 上，輸出點就是 Portal，由 Integration 服務做媒介與位址的轉換。802.11 只定義這些「服務」，不規定 DS 要怎麼實作。
橋接器 vs Portal：橋接器原本是用來延伸同類 MAC 的範圍；在 802.11 中，涵蓋範圍改由 ESS 提供。要接到異質 LAN 時，講義問「接到 DSM 還是 WM」→ 用 Portal，因為它還要處理 BSS 成員的動態變化，以及位址與位置的對應。
兩類服務：SS（每台站台都有）＝認證、解除認證、隱私、MSDU 傳遞；DSS（由 DS 提供）＝關聯、重新關聯、解除關聯、分配、整合；802.11e 再加上 QoS 相關服務。考古題 Q3C。
名詞：DS＝分散式系統。DSM＝DS 使用的媒介。WM＝無線媒介。Portal＝802.11 與其他 LAN 之間的出入口。SS／DSS＝站台服務／分散式系統服務。

K17標頭欄位

  • Duration/ID：一般放微秒數，別人用它設 NAV；CFP 中送的訊框固定放 32768；PS-Poll 改放 AID，讓 AP 知道是誰來取資料。考古題 Q3D。
  • More Data：AP 告訴省電中的站台「還有緩衝資料」；或 STA 表示還有資料可以在下次 CF-Poll 時送。考古題 Q3B。
  • Retry：這是重傳的訊框，接收端用來刪除重複。
  • Pwr Mgt：1 表示傳送者之後要進入省電；AP 送出的訊框永遠是 0。
  • More Frag：後面還有分段。
  • Sequence Control：12 位元序號＋4 位元分段號。

K18WEP／隱私

目的補回有線網路「封閉媒介」所提供的機密性。
運作使用 RC4，金鑰 40 位元加上 24 位元的 IV；用 ICV 檢查完整性；只加密資料訊框的 payload，每個 MPDU 各自加密；ICV 錯誤時照樣回 ACK，但把訊框丟掉；關聯之前要議定隱私演算法。
缺點只保護無線這一段，不是端對端；金鑰分配沒有標準化；已被破解，後來由 802.11i 取代 補充。
名詞：WEP＝有線等效隱私。RC4＝串流加密演算法。IV＝初始向量，每個訊框不同，和金鑰一起產生金鑰序列。ICV＝完整性檢查值。

K19PLCP 與多速率

Long PLCP：前導碼 144 位元＋標頭 48 位元，都用 1 Mbps 送 → 192 µs；Short PLCP：96 µs。
為何用最低速率：最低速率最穩健、每個站台都聽得懂，所以不論資料用什麼速率，大家都能同步並讀到 SIGNAL（速率）與 LENGTH 欄位。LENGTH 是「資料要傳幾微秒」，聽不懂資料部分的站台也能知道媒介何時空出來，等於一種虛擬載波偵測。
速率選擇不在標準內（常見做法是依 ACK 成敗或訊號品質升降速率 補充）。一個 BSS 用一個頻道（FHSS 是全體一起跳頻）；要用多個頻道就是多個 BSS 放在同一地點 補充。
802.11g 保護：BSS 中有 11b 站台時，先送 CTS（用 11b 聽得懂的速率）設定 NAV，再用 OFDM 送資料。減少 PHY 負擔：short preamble 96 µs（11b）、short slot 9 µs（11g；BSS 中有舊站台就不能用）。
名詞：PLCP＝實體層匯聚協定。preamble＝前導碼，讓接收端同步。OFDM＝正交分頻多工。FHSS＝跳頻展頻。

K20調變與展頻

DSSS：每個位元用 11 chip 的 Barker 序列表示，處理（編碼）增益 10.4 dB → 抗干擾、抗延遲擴散、能分辨多路徑回波；代價是頻寬變寬（每個訊號約 22 MHz 補充）。2.4 GHz 頻道中心間隔 5 MHz，互不重疊的只有 1、6、11，所以重疊的 BSS 最多 3 個。
鍵控：PSK 改變相位、FSK 改變頻率、ASK 改變振幅。QAM：同相 I（cos）與正交 Q（sin）兩個載波各做 ASK 再相加，等於 PSK 與 ASK 的組合；802.11a/g 的 24、36 Mbps 用 16-QAM，48、54 Mbps 用 64-QAM；每個符元帶的位元越多，越需要好的訊號品質（SNR）補充。DBPSK 每符元 1 位元、DQPSK 每符元 2 位元。考古題 Q3A。
名詞：DSSS＝直接序列展頻。chip＝展頻序列中的一個碼元。Barker 序列＝802.11 DSSS 使用的 11 chip 序列。延遲擴散＝多路徑造成訊號先後抵達。SNR＝訊雜比。DBPSK／DQPSK＝差分二元／四相位移鍵控。

K21EDCA

目的優先式 QoS：只給相對的高低，不保證數值。
運作每個訊框帶 UP（8 個值，和 802.1D 相同，所以有線網路的優先權標記可以直接帶進來）→ 對應到 AC：UP 1、2 → BK；0、3 → BE；4、5 → VI；6、7 → VO。競爭發生在 AC 之間，每個 AC 有自己的 AIFS、CW、TXOP limit；這些參數由 AP 在 Beacon 的 EDCA Parameter Set 宣告（ACM 位元表示該 AC 必須經過允入控制）。預設值：VO 是 AIFSN 2＋退避 0–3 slot、VI 是 2＋0–7、BE 是 3＋0–15、BK 是 7＋0–15。
優點分散式、和 DCF 相容、AP 可以動態調整參數。
缺點統計式，不保證延遲；低優先權的流量可能餓死；同一台站台內不同 AC 之間也可能內部碰撞 補充。
名詞：EDCA＝增強型分散式通道存取。UP＝使用者優先權。AC＝存取類別：VO 語音、VI 影像、BE 盡力而為、BK 背景。ACM＝允入控制強制位元。

K22HCCA、TSPEC、允入控制

目的參數化 QoS：保證具體數值（例如 10 Mbps、10 ms 延遲上限）。
運作QSTA 送 ADDTS Request（內含 TSPEC）→ HC 判斷能不能允入 → 回 ADDTS Response → HC 依 TSPEC 排輪詢時程 → 送 QoS CF-Poll → QSTA 在 Polled TXOP 內傳送。CFP 與 CP 都可以輪詢；這類流量的 TID 是 8–15；用 DELTS 刪除。
優點可以保證頻寬與延遲。對比 PCF 逐點改進：一次一個訊框 → 一段 TXOP；不知道需求 → TSPEC；沒有保證 → 排程加允入控制。考古題 Q6 可以用這段收尾。
缺點需要 HC、複雜、只能用在 infrastructure、仍有隱藏站問題。允入控制的意義：通道時間有限，不超賣才能守住已經允諾的保證。
名詞：HCCA＝HCF 控制通道存取。HC＝混合協調器（在 QAP 上）。TSPEC＝流量規格（速率、服務間隔、延遲上限……）。ADDTS／DELTS＝新增／刪除流量串流。TID＝流量識別碼，0–7 是 UP、8–15 是 TSPEC 註冊的流。QSTA／QAP＝支援 802.11e 的站台／AP。

K23TXOP

一段有開始時間與最長長度的傳送機會。EDCA TXOP：贏得競爭取得，上限由 Beacon 宣告；Polled TXOP：收到 QoS CF-Poll 取得，上限寫在 QoS Control 欄位。TXOP 內各訊框用 SIFS 連送；長度以 32 µs 為單位，範圍 32–8160 µs。
優點一次競爭送多筆，分攤競爭負擔；用時間（不是訊框數）限制佔用，所以延遲可控。缺點TXOP 越長，其他人等得越久；所以語音給短的、影像給長的。

K24ACK 政策與 Block Ack

四種 ACK 政策：Normal（SIFS 後回 ACK）、No Ack、No explicit Ack、Block Ack。Block Ack 流程：ADDBA 建立（TID、政策、緩衝大小、逾時）→ QoS Data 連續送出 → BAR（要求確認）→ BA（點陣圖，最多涵蓋 64 個 MSDU）→ DELBA 結束。
Immediate：BAR 之後立刻回 BA，適合高頻寬、低延遲的流量。Delayed：BAR 先回一般 ACK，之後再送 BA，適合能容忍中等延遲的應用。優點省下每筆的 SIFS＋ACK。缺點需要事先建立、接收端要緩衝並重新排序。No Ack 適合語音（晚到的重傳沒用）補充。
名詞：ADDBA／DELBA＝建立／刪除 Block Ack 協議。BAR＝Block Ack Request。BA＝Block Ack。

K25DLS

兩個 QSTA 先經過 QAP 交換 DLS Request／Response——經過 QAP 是因為接收端可能在省電、需要 QAP 叫醒，而且雙方要交換能力資訊 → 之後兩者直接互傳 → 超過 DLPTimeout 沒有流量就失效，回到經過 AP 的路徑；直接鏈路存在期間接收端不能進入省電。它解決的是「全部經過 AP，頻寬用兩倍」的缺點（K27）。
名詞：DLS＝直接鏈路建立。DLPTimeout＝直接鏈路的閒置逾時。

K26APSD

U-APSD（WMM Power Save，以 EDCA 為基礎）：STA 醒來送一個 trigger 訊框（通常就是自己的上行資料）→ 開始一段服務期間 SP → QAP 送出 delivery-enabled AC 的緩衝訊框（最多 Max SP Length：全部、2、4 或 6 個）→ 用 EOSP 標示結束。S-APSD（以 HCCA 為基礎）：用 ADDTS 協商一個排程，STA 定時醒來接收。
VoIP 例子：語音每 20 ms 一包、延遲要小於 20 ms。用 U-APSD 時，上行語音本身就是 trigger，所以不必等 Beacon（解決 K11 的 100–300 ms 延遲），也省掉 PS-Poll；其他 AC 仍然走 PS-Poll。
名詞：APSD＝自動省電傳送。U-／S-APSD＝非排程式／排程式。SP＝服務期間。EOSP＝服務期間結束位元。WMM＝Wi-Fi 聯盟依 802.11e 訂的認證規格。

K27架構與 AP

三種架構：IBSS（ad hoc）、Infrastructure（AP＋DS）、Mesh。BSS＝由單一協調功能控制的一群 STA；AP＝一個 STA 加上存取 DS 的能力。802.11 只標準化空中介面（PHY＋MAC）。
全部經過 AP 的取捨：缺點STA 對 STA 的流量用掉兩倍頻寬，競爭與碰撞也變多；優點輕易解決隱藏終端問題（大家都聽得到 AP）、可以替省電站台緩衝、符合 AAA 架構、可以做每個流的 QoS。
名詞：BSS＝基本服務集。Mesh＝網狀網路。AAA＝認證、授權、計費。
