🧾 IEEE 802.11 WEP 隱私與 MAC 訊框格式

PDF 共 32 頁，對應投影片第 1–33 頁；第 22 頁不在 PDF 中 待確認。本章接續 2-2「IEEE 802.11 MAC 架構與服務」：2-2 講 Authentication、Association、Privacy 這些服務，這一章講它們實際用到的訊框長什麼樣子。

本章講 802.11 的服務實際用到的訊框：WEP 怎麼加密，以及 MAC 訊框每個欄位的意義。

  • WEP：802.11 原始的選用加密，用 RC4＋24-bit IV，只加密資料訊框的 payload、只保護無線這一段。補充已被破解，由 802.11i（WPA2）取代。
  • 站台狀態：State 1／2／3 決定能送 Class 1／2／3 訊框；Deauthentication 退回 State 1，Disassociation 退回 State 2。
  • MAC 訊框＝Header＋Frame Body（0–2312 bytes）＋FCS；To DS／From DS 決定 4 個位址欄位怎麼填。
  • 三類訊框：控制（RTS、CTS、ACK、PS-Poll）、資料、管理（Beacon、Probe、Authentication、Association）。

2. 隱私與存取控制：WEP（p.1–2）（Privacy and Access Control）

  • 802.11 的目標是提供有線等效隱私（Goal of 802.11 is to provide Wired Equivalent Privacy (WEP)），而且全球通用（Usable worldwide）。白話：有線網路要接上線才聽得到，電波誰都收得到，至少要讓旁人聽到也看不懂。
  • 802.11 提供 Authentication 機制協助存取控制（To aid in access control），可用 Open System、Shared Key 或廠商自訂延伸（proprietary authentication extensions）。
  • WEP 是 802.11 定義的選用隱私機制（Optional (WEP) Privacy mechanism）：
    • 只保護站台對站台的流量，不是 end to end（Limited for Station-to-Station traffic, so not "end to end"）；嵌在 MAC 實體內（Embedded in the MAC entity）。
    • 只實作機密性（Only implements Confidentiality function）。
    • 使用 RC4 PRNG：seed = 40-bit 秘密金鑰（標準沒規定金鑰怎麼發放，靠外部金鑰管理服務）＋ 24-bit IV（隨資料送出）＝ 64 bits（新版 128、152 bits）。
    • 附 ICV 做完整性檢查（includes an ICV to allow integrity check）。
    • 只加密資料訊框的 payload（Only payload of Data frames are encrypted），以每個 MPDU 為單位（Encryption on per MPDU basis）。

3. 隱私服務（p.3–4）（Privacy Service）

  • 定義：防止訊息內容被預期接收者以外的人讀取的服務。
  • 有線 LAN 只有實體接上線的站台才聽得到流量（only those stations physically connected to the wire can hear LAN traffic）；802.11 不是這樣，所以提供加密訊息內容的能力。
  • 提供 MIB 功能，可查詢站台支援哪些加密演算法（A MIB function is provided to inquire the encryption algorithms supported by a station）。
  • 建立 Association 之前，雙方必須先談好都能接受的隱私演算法（A mutually acceptable privacy algorithm must be agreed upon before an Association can be established）。
  • 預設是明文（The default privacy algorithm for all 802.11 stations is in the clear）：沒啟動隱私服務時全部不加密；一旦設定，之後的傳輸都會使用。
  • 即使 Association 成功，之後的 Reassociation 仍可能被拒絕（Even if an Association is successful, a later Reassociation may be refused）。
  • 802.11 規定的是選用的隱私演算法，目標是達到有線 LAN「等效」的隱私。

⚠️ 講義勘誤（p.3）

原文：「The service used to prevent the contents of messages by other than the intended recipient.」
正確：「…prevent the contents of messages from being read by other than the intended recipient.」

理由：原句少了動詞片語，意思不完整；標準原文有「from being read」。

5. ESS 與 IBSS 的差異（p.10）（Differences Between ESS and Independent BSS LANs）

  • IBSS 常用來支援「Ad-Hoc」網路，站台直接與一或多個站台通訊。
  • IBSS 在邏輯上是 ESS 的子集（a logical subset of an ESS），由直接相連的站台組成。
  • 沒有實體 DS，所以沒有 Portal、沒有整合的有線 LAN、沒有 DS 服務（there cannot be a Portal, an integrated wired LAN, or the DS Services）。
  • IBSS 只允許 Class 1 訊框；可用的服務只有站台服務：① Authentication ② Deauthentication ③ Privacy ④ MSDU delivery。

6. MAC 訊框格式（p.11–13）（Frame and MPDU Formats）

  • 每個訊框由三部分組成：
    • MAC Header：控制資訊、位址、序號、分段識別、Duration、QoS 資訊（control information, addressing, sequencing fragmentation identification, duration, and QoS information）。
    • Frame Body：可變長度，內容依訊框類型而定。
    • FCS：IEEE 32-bit 循環冗餘碼（CRC）。
  • MAC Header 依類型而異：控制訊框省略部分欄位（1 或 2 個位址）、管理訊框 3 個位址、資料訊框 4 個位址。
  • Sequence Control 用來過濾 ACK 機制（ACK 遺失後重傳）造成的重複訊框（filtering of duplicate caused by ACK mechanism）。
  • 補充資料訊框只有 To DS = From DS = 1 時才真的帶 Addr 4；其他情況標頭為 24 bytes。

8. Duration/ID 欄位（p.15–16）（Duration/ID Field）

To DS／From DS 與四個位址 動畫
STA A 要把一筆 MSDU 交給 STA B。看封包這一跳從誰到誰，Addr 1 永遠是這一跳的接收端，Addr 2 永遠是這一跳的傳送端。
  • Addr 1：所有站台都用它過濾「是不是給我的」（All stations filter on this address）。
  • Addr 2：傳送端位址（TA），用來知道 ACK 要回給誰（Identifies transmitter to address the ACK frame to）。
  • Addr 3：依 To DS／From DS 而定。Addr 4：只有在 WDS 需要標出原始來源時才用。
  • BSSID：Infrastructure = AP 的 MAC 位址；Ad hoc = 「01 ＋ 46-bit 亂數」（講義：may set as ‘1’）。
    • 補充標準規定 IBSS 的 BSSID 取 46-bit 亂數，Individual/Group 位元設 0、Universal/Local 位元設 1，依傳送順序就是開頭的「01」。
    • 待確認 p.13 的「(may set as ‘1’)」指哪一個 bit 設 1 不明確，推測是 U/L 位元，請對照上課說明。

10. Sequence Control 與分段（p.17）（Sequence Control）

  • Sequence Number（12 bits）：遞增值；同一個 MSDU 的所有分段用同一個序號（The same value shall be used for all fragments of the same MSDU）。
  • Fragment Number（4 bits）：每個分段的編號。
  • Frame Body：0–2312 bytes；CRC：4 octets。

⚠️ 講義勘誤（p.17）

原文：Fragment Number 旁註「At least 16 fragments」。　正確：「At most 16 fragments」。

理由：4 bits 只能表示 0–15，一個 MSDU 最多切 16 段，是上限不是下限。

把一個 MSDU 切成分段 動畫
依講義第 17 頁圖延伸。每段都要自己的 MAC Header（3 位址 24 bytes）與 CRC（4 bytes）；「每段上限」是自訂例子，講義沒有給分段門檻。

12. 資料訊框（p.21、23）（Data Frames）

  • 位址欄位內容依 To DS／From DS 而定；站台用 Address 1 做收件判斷（address matching for receive decisions）。
  • DA 是 MSDU 的最終目的地；RA 是無線 DS 中下一個直接接收的 AP；TA 是無線 DS 中正在傳送的 AP。
  • BSSID：站台是 AP 或關聯到 AP 時 = AP 位址；ad hoc 成員時 = ad hoc LAN 的 BSS ID。
  • Null function、CF-Ack、CF-Poll、CF-Ack+CF-Poll 這幾種「no data」子類型，Frame Body 長度為 0。
  • p.23「Data Frames (IEEE 802.11 ax)」圖多了 QoS（0 或 2 bytes）與 HT（0 或 4 bytes，High Throughput）欄位，可在第 6 節的瀏覽器選「資料訊框（p.23）」查看。
  • 補充QoS Control 由 802.11e 加入，只有 QoS 資料訊框才有；HT Control 由 802.11n 加入，11ac／ax 沿用並延伸成 VHT／HE 變體。講義標題寫 11ax，指到 11ax 為止的格式。
  • 補充圖上 Sequence Number 與 Fragment Number 分兩格，實際上都在 2 bytes 的 Sequence Control 內（12 ＋ 4 bits）。

13. 訊框交換順序（p.24）（Frame Exchange Sequences）

  • Data（補充廣播／群播，不回 ACK）・Data – ACK・RTS – CTS – Data – ACK
  • Data – ACK – Data – ACK（分段的 MSDU）・RTS – CTS – Data – ACK – Data – ACK（分段的 MSDU）
  • Poll – Data – ACK（STA to AP）・Poll – Data – ACK – Data – ACK（分段）・Poll – ACK（No data 或 More data）
  • ATIM – ACK（Ad hoc 省電）・Request（管理：Probe Request）・Request – ACK、Response – ACK（管理）
  • CTS – Data、CTS – Management、CTS – Data – ACK、CTS – Data – ACK – Data – ACK（11g）

17. 公式與計算

每個公式先寫出來、說明符號，再代入範例數值一步一步算。單位提醒：1 byte = 8 bits；R 以 Mbps 表示時等於「每 µs 幾個 bits」，所以 bits ÷ Mbps 直接得到 µs。

MAC 訊框長度

LMPDU = Lhdr + Lbody + LFCS（bytes；Lbody 為 0–2312，LFCS = 4）

符號：Lhdr＝MAC 標頭；Lbody＝Frame Body；LFCS＝CRC-32 檢查碼。

  1. 4 位址標頭逐欄相加：Frame Control 2 + Duration/ID 2 + Address 1–3 共 6×3 = 18 + Sequence Control 2 + Address 4 6 → 2 + 2 + 18 + 2 + 6 = 30 bytes。
  2. 3 位址（沒有 Address 4）：30 − 6 = 24 bytes。
  3. 最大資料訊框：30 + 2312 + 4 = 2346 bytes；3 位址為 24 + 2312 + 4 = 2340 bytes。
  4. 控制訊框：RTS = FC 2 + Duration 2 + RA 6 + TA 6 + FCS 4 = 20；CTS = ACK = 2 + 2 + RA 6 + 4 = 14；PS-Poll = 2 + AID 2 + BSSID 6 + TA 6 + 4 = 20；CF-End 同樣 20 bytes。

訊框傳輸時間

T = 8 × L ÷ R（T：µs；L：bytes；R：Mbps，等於 bits/µs）
  1. ACK：L = 14 bytes → 14 × 8 = 112 bits。
  2. 1 Mbps：112 ÷ 1 = 112 µs；11 Mbps：112 ÷ 11 ≈ 10.18 µs。
  3. 最大資料訊框：2346 × 8 = 18768 bits；18768 ÷ 11 ≈ 1706.2 µs。
  4. 補充加上 802.11b 長前導 PLCP 192 µs：1706.2 + 192 = 1898.2 µs；ACK 在 11 Mbps 則是 10.18 + 192 ≈ 202.2 µs，PLCP 佔了 95%。

計算陷阱：bytes 要 ×8；PHY 的 Preamble 與 PLCP Header 要另外加，短訊框時它才是主角。

Duration/ID 數值

Dmax = 215 − 1 = 32767 µs　DCFP = 215 = 32768　PS-Poll 欄位值 = 215 + 214 + AID = 49152 + AID
  1. 欄位 16 bits，bit 15 = 0 時剩 15 bits 表示時間：最大 215 − 1 = 32768 − 1 = 32767 µs（約 32.8 ms）。
  2. CFP 期間只設 bit 15 = 1、其餘 0：215 = 32768。
  3. PS-Poll 設 bit 15 = bit 14 = 1：215 + 214 = 32768 + 16384 = 49152（0xC000），低 14 bits 放 AID。
  4. AID = 5：49152 + 5 = 49157（0xC005）。
  5. 最大 AID 2007 → 49152 + 2007 = 51159（0xC7D7）；2007 = 0x7D7，所以只是把 0xC000 的低位補上 0x7D7。

計算陷阱：PS-Poll 的這兩個 bytes 不是時間，不能拿來更新 NAV。

Sequence Control 範圍

Nseq = 212 = 4096（0–4095，用完從 0 重來）　Nfrag = 24 = 16　分段數 = ⌈LMSDU ÷ Lfrag⌉
  1. Sequence Number 12 bits：212 = 4096 個值（0–4095）；Fragment Number 4 bits：24 = 16（0–15）。
  2. 例：2000 bytes 的 MSDU，每段 Frame Body 最多 600 bytes（自訂數字）→ 2000 ÷ 600 = 3.33，無條件進位 = 4 段（600、600、600、200）。
  3. 每段都要自己的標頭與 FCS：24 + 4 = 28 bytes；4 段共 4 × 28 = 112 bytes。
  4. 總長 2000 + 112 = 2112 bytes；不分段只需 2000 + 28 = 2028 bytes，多出 2112 − 2028 = 84 bytes。

WEP 種子長度與 IV 空間

Lseed = Lkey + LIV　NIV = 224 = 16,777,216　用完時間 = NIV ÷ 每秒訊框數
  1. 40 + 24 = 64；104 + 24 = 128；128 + 24 = 152（補充104、128 是由講義的 128、152 倒推）。
  2. IV 有 24 bits：224 = 210 × 210 × 24 = 1024 × 1024 × 16 = 16,777,216 種。
  3. 補充11 Mbps、每框 1500 bytes = 12000 bits：每秒 11×106 ÷ 12000 ≈ 916.7 框。
  4. 16,777,216 ÷ 916.7 ≈ 18,302 秒；÷ 3600 ≈ 5.1 小時就會重複 IV。
  5. 補充若 IV 是隨機選，依生日問題約 1.18 × √(224) = 1.18 × 4096 ≈ 4823 框就有一半機率撞到重複 IV，換算 4823 ÷ 916.7 ≈ 5 秒。同 IV ＋ 同金鑰 → 同金鑰序列，這是 WEP 被破解的原因之一。

計算陷阱：「64-bit WEP」含 IV，真正的秘密只有 40 bits。

WEP 額外負擔

Lbody,WEP = LMSDU + 4（IV 欄位）+ 4（ICV）
  1. IV 欄位 = IV 24 bits + Pad 6 bits + Key ID 2 bits = 32 bits = 4 bytes；ICV 是 CRC-32 = 4 bytes。
  2. 例：MSDU 1500 bytes → 1500 + 4 + 4 = 1508 bytes。
  3. 補充標準 MSDU 上限 2304 bytes → 2304 + 8 = 2312，正好是講義的 Frame Body 上限。

補充2.4 GHz 頻道中心頻率

fc(n) = 2407 + 5n MHz，n = 1…13
  1. 北美 Set 1 是頻道 1、6、11：2407 + 5×1 = 2412、2407 + 5×6 = 2437、2407 + 5×11 = 2462 MHz → 間距 2437 − 2412 = 25 MHz。
  2. 歐洲 Set 1 是頻道 1、7、13：2412、2407 + 35 = 2442、2407 + 65 = 2472 MHz → 間距 30 MHz。
  3. Set 2 相隔 2 個頻道：2 × 5 = 10 MHz。
  4. 和 DSSS 頻寬約 22 MHz 比：25、30 ≥ 22 不重疊；10 < 22，重疊 22 − 10 = 12 MHz，所以叫「半重疊」。

19. 複習問題

觀念題

1. WEP 提供了哪些安全功能？為什麼說它不是 end to end？
WEP 只實作機密性，用 RC4 加密資料訊框 payload，並用 ICV 檢查完整性。它嵌在 MAC 內，只保護站台到站台（例如 STA 到 AP）的無線鏈路，進入 DS 或有線網路後就是明文。
2. 三種站台狀態各可送哪些訊框？Disassociation 與 Deauthentication 各退回哪個狀態？
State 1 只能 Class 1；State 2 可 Class 1、2；State 3 可 Class 1、2、3。Disassociation 從 State 3 退回 State 2；Deauthentication 退回 State 1。
3. 為什麼 IBSS 只允許 Class 1 訊框？
IBSS 沒有實體 DS，沒有 Portal 與 DS 服務；Association 是 DS 服務，在 IBSS 不需要。站台之間直接傳資料（To DS = From DS = 0），這類資料訊框屬於 Class 1。
4. To DS = 1、From DS = 0 時，Address 1～3 各放什麼？為什麼 Addr 1 是 BSSID？
Addr 1 = BSSID、Addr 2 = SA、Addr 3 = DA。這一跳的接收者是 AP，而所有站台用 Addr 1 過濾收件，所以 Addr 1 放 AP 位址（Infrastructure 下 BSSID 就是 AP 的 MAC）；最終目的地 DA 放 Addr 3 讓 AP 轉送。
5. Sequence Control 的用途？為什麼分段要用同一個序號？
用來過濾 ACK 遺失造成的重複訊框。同一 MSDU 的分段共用序號，接收端才能辨認是同一筆資料，再依 Fragment Number 重組。

計算題

6. 4 位址資料訊框的最大 MPDU 長度？11 Mbps 下的傳輸時間（不含 PLCP）？
標頭 = 2+2+6+6+6+2+6 = 30 bytes；最大 MPDU = 30 + 2312 + 4 = 2346 bytes。2346 × 8 = 18768 bits；T = 18768 ÷ 11 ≈ 1706.2 µs。
7. AID = 100 的 PS-Poll，Duration/ID 的十進位與十六進位值？
bit 15、14 設 1 → 32768 + 16384 = 49152（0xC000）。49152 + 100 = 49252；100 = 0x64，所以是 0xC064。可以用第 8 節的解碼器驗證。
8. 104-bit 金鑰的 WEP，種子幾 bits？AP 每秒送 2000 框、IV 逐框加 1，多久必定重複？
種子 = 104 + 24 = 128 bits。224 = 16,777,216；16,777,216 ÷ 2000 ≈ 8388.6 秒 ≈ 2.33 小時。

情境應用題

9. 筆電連上咖啡廳的 AP 後，AP 突然重開機，接著收到筆電的資料訊框，會發生什麼？
AP 重開後沒有筆電的認證紀錄，筆電對 AP 而言在 State 1。依講義 p.8 的 PS，AP 收到未認證站台的 Class 3 訊框會回 Deauthentication。筆電回到 State 1，要重新 Authentication（State 2）再 Association（State 3）才能繼續傳資料。
10. 2.4 GHz 要部署三台相鄰 AP，北美應選哪些頻道？歐洲呢？
北美選 1、6、11：2412、2437、2462 MHz，間距 25 MHz，大於 DSSS 約 22 MHz 頻寬，彼此不重疊。歐洲選 1、7、13：2412、2442、2472 MHz，間距 30 MHz，同樣不重疊且間隔更寬。

20. 一頁速記

  1. WEP = RC4，seed = 40-bit 金鑰 + 24-bit IV = 64 bits（新版 128／152）；只加密資料 payload，只保護無線這一段。
  2. IV 欄位 4 bytes = IV 3 bytes + Pad 6 bits + Key ID 2 bits（4 把金鑰）；ICV 4 bytes；ICV 錯也回 ACK 再丟棄。
  3. 預設不加密；Association 前要先談好隱私演算法。
  4. State 1／2／3 ↔ Class 1／1+2／1+2+3；Deauth 回 1、Disassoc 回 2；IBSS 只用 Class 1。
  5. MAC 訊框 = Header + Body（0–2312）+ FCS（4）；最大 30 + 2312 + 4 = 2346 bytes。
  6. Frame Control 16 bits：Ver 2、Type 2、Subtype 4、To DS、From DS、More Frag、Retry、Pwr Mgt、More Data、WEP、Order。
  7. Duration 0–32767 µs；CFP 固定 32768；PS-Poll 放 AID（bit 15、14 = 1，1–2007）。
  8. To DS 1 → Addr 1 = BSSID；From DS 1 → Addr 2 = BSSID；兩者皆 1 → RA、TA、DA、SA。
  9. RTS 20 B、CTS／ACK 14 B；Subtype：PS-Poll 1010、RTS 1011、CTS 1100、ACK 1101、CF-End 1110、CF-End+Ack 1111。
  10. Capability：B0 ESS、B1 IBSS、B4 Privacy、B5 短前導、B10 9 µs 短時槽、B13 DSSS-OFDM；頻道 1/6/11 間距 25 MHz、1/7/13 間距 30 MHz。

22. 考前自我檢查

  • 畫出 WEP 加密／解密流程，說明 seed、IV、ICV 的角色
    seed = IV（24）‖ Secret Key（40）→ RC4 產生金鑰序列；（明文 ‖ ICV）⊕ 金鑰序列 = 密文；IV 明文送出，接收端重組 seed 解密後比對 ICV' = ICV。
  • 拆解 WEP 的 4-byte IV 欄位並算出可用金鑰數
    IV 3 bytes（24 bits）＋ Pad 6 bits ＋ Key ID 2 bits；2² = 4 把金鑰。
  • 說出 ICV 錯誤時接收端怎麼處理
    仍回 ACK，但丟棄訊框（ACKed but discarded）。
  • 畫出 State 1／2／3 狀態圖並標出轉換事件
    1 →（Authentication）→ 2 →（Association／Reassociation）→ 3；3 →（Disassociation）→ 2；2、3 →（Deauthentication）→ 1。
  • 把 RTS、Beacon、Association Request、PS-Poll 分到 Class 1／2／3
    RTS、Beacon：Class 1；Association Request：Class 2；PS-Poll：Class 3。
  • 畫出 MAC 訊框格式、寫出欄位長度並算出 2346 bytes
    FC 2、Duration/ID 2、Addr1 6、Addr2 6、Addr3 6、Seq Ctrl 2、Addr4 6、Body 0–2312、FCS 4 → 30 + 2312 + 4 = 2346。
  • 背出 Frame Control 11 個子欄位與 bit 數
    Protocol Version 2、Type 2、Subtype 4、To DS、From DS、More Frag、Retry、Pwr Mgt、More Data、WEP、Order 各 1。
  • 依 To DS／From DS 填出 Address 1～4
    00：DA、SA、BSSID；01：DA、BSSID、SA；10：BSSID、SA、DA；11：RA、TA、DA、SA。
  • 解讀 Duration/ID 的 bit 15、14，算出 PS-Poll 的欄位值
    bit 15 = 0 → Duration（µs）；10 + 全 0 → CFP 32768；11 + 1–2007 → AID，欄位值 = 49152 + AID。
  • 說明 Sequence Number 與 Fragment Number 的用途與上限
    Sequence 12 bits（0–4095），同一 MSDU 的分段共用，用來去重；Fragment 4 bits（0–15），最多 16 段，用來重組。
  • 畫出 RTS、CTS、ACK、PS-Poll 的欄位並說出 Subtype
    RTS 1011：FC、Duration、RA、TA、FCS；CTS 1100、ACK 1101：FC、Duration、RA、FCS；PS-Poll 1010：FC、AID、BSSID、TA、FCS。
  • 說出 Beacon 與 Probe Response、Association 與 Reassociation Request 的差異
    Probe Response 省略 TIM；Reassociation Request 多一個 Current AP address。
  • 寫出 Shared Key 認證四步驟
    ① STA 要求（序號 1）② AP 回 challenge text（序號 2）③ STA 用 WEP 加密 challenge 送回（序號 3）④ AP 回結果（序號 4）。
  • 解讀 Capability 的 ESS／IBSS 與 CF-Pollable／CF-Poll Request
    AP：ESS 1、IBSS 0；IBSS 站台：ESS 0、IBSS 1。CF 兩個 bit 依送出者（STA 或 AP）查第 15 節的表。
  • 算出頻道 1／6／11、1／7／13 的中心頻率與間距
    2412、2437、2462 MHz（間距 25）；2412、2442、2472 MHz（間距 30）。
